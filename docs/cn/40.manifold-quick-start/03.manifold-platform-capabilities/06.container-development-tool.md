妙算 3 内置了一套受控容器管理工具（`box-*` 命令集），在底层封装 Docker，对外暴露经过安全收敛的命令，开发者无需 root 权限即可使用容器能力。所有命令与 docker 风格一致，容器内的权限、资源、端口、文件挂载由平台统一预置，镜像内容与命名由开发者自主管理。

## 基础说明

`box-*` 命令在底层封装 Docker，命名规则为 `box-<docker 子命令>`，与 docker 子命令**一一对应**，但仅开放安全白名单子集，不支持直接使用 `docker` 命令。主要支持：

- 创建和管理开发容器
- 进入容器进行开发调试
- 保存、导出/导入、拉取自定义环境镜像
- 透传 host 物理设备（USB-Serial / 摄像头 / GPIO / I2C / PSDK USB 等）
- 在容器内运行 Python、AI 推理、模型验证等程序
- 使用 NVIDIA GPU 进行推理验证

系统已预置 `box-dev`（开发）、`box-dpk`（服务）等官方基础镜像，可直接使用。

:::warning 注意
- 系统不开放 `docker` 命令，所有容器操作须通过 `box-*` 命令执行。
- 容器内以 root 身份运行，可直接安装依赖、修改容器内文件；容器与宿主机相互隔离，容器内的 root 权限不作用于宿主机，宿主机侧仍使用您自己的登录账号（不提供宿主机 root）。
- host 网络默认禁用；PSDK 等需要与宿主机一致网络视图的业务可通过 `--network host` 显式开启（详见 [box-run](#box-run) 章节）。
- 每个用户仅可管理自己创建的容器和镜像。
- 容器内 `/workspace` 目录与 host 侧 `~/box/workspace` 双向挂载，其余路径的数据在容器删除后将被清除（需提前执行 commit）。
- 容器异常退出时 docker 默认会自动重启（平台预置 `--restart=unless-stopped`）。
:::

:::tip 说明：
任意 `box-*` 命令均可加 `-h` / `--help` 查看完整帮助（含选项含义、限制、退出码、示例）。
:::

## 容器与 DPK 的关系

容器（Docker）与 DPK 两种部署方式互斥，请根据业务场景选择其一。

| 场景 | 说明 |
|:---|:---|
| DPK | 轻量级应用软件包，分发方便。安装包可通过 Pilot 安装、卸载、启动与管理，可直接面向最终用户使用。 |
| Docker 容器 | 适用于深度定制化或项目制场景。可打包为 Docker 镜像进行分发和批量安装，需通过系统控制台配置镜像或安装软件，面向开发者或专业交付团队。 |

:::warning 注意
1. 使用 DPK 部署时，不建议同时在 Docker 容器中运行 PSDK 程序，可能存在端口冲突。
2. 使用 Docker 容器开发 PSDK 应用时，不建议同时使用 DPK 方式部署，可能导致 Pilot 无法正常安装和管理 DPK 应用。
:::

:::tip 运行 PSDK 程序：
在容器内运行 PSDK 程序前，需先将对应的 USB 通道透传至容器，随后即可运行编译好的 PSDK 可执行文件（如 <a href="../quick-demo.html#运行-demo" target="_blank">运行 Demo</a> 章节中编译产出的 `dji_sdk_demo_on_manifold3`）。透传方式取决于所采用的 PSDK 连接方案：

- **USB bulk 方案**（编译产物位于 `build-manifold3-usbbulk/`）：须使用 `--functionfs` 透传 FunctionFS 端点目录，并附加 `--network host`，详见 [box-run](#box-run) 章节中的「PSDK USB 透传说明」。
- **串口方案**：外接设备为字符设备（如 `/dev/ttyACM0`）时，使用 `--device` 透传即可。
:::

## 核心概念

容器开发涉及以下几个核心概念，理解它们有助于使用后续命令：

| 概念 | 说明 |
|:---|:---|
| 镜像（image） | 只读的环境模板，包含运行所需的系统、依赖和配置，可类比为面向对象中的「类」，自身不可运行。系统预置了 `box-dev`、`box-dpk` 等官方镜像，也可通过 `box-pull` 拉取、`box-load` 加载或 `box-commit` 生成。 |
| 容器（container） | 由镜像启动的运行实例，可类比为「类」实例化后的「对象」。容器可读写且相互隔离，开发调试均在容器内进行。 |
| 提交（commit） | 将容器的当前状态（如已安装的依赖）保存为新的环境镜像，供后续复用，相当于将已配置的环境保存为新模板。镜像名称可自定义。 |
| workspace | 容器与主机共享的工作目录，其中的数据在容器删除后仍会保留（详见下方「workspace 工作目录」）。 |

### workspace 工作目录

| 位置 | 路径 |
|:---|:---|
| 主机上 | `~/box/workspace`（实际位于大容量分区 `/open_app/workspaces/<user>/box/workspace`，`~/box` 为指向该目录的软链接） |
| 容器内 | `/workspace` |

- 放进 workspace 的文件在主机和容器间**双向可见**。
- workspace 之外的主机文件，容器内无法访问。
- 存放于容器其他路径（如 `/tmp`）的文件，在执行 `box-rm` 删除容器后将被清除。如需保留，须在删除前执行 `box-commit`。

### 端口

只能开放 20000-20100 范围内的端口，host 与 container 同号，只绑定 `127.0.0.1`（设备外部不可达）。

| docker rename | [box-rename](#box-rename) | 重命名容器 | <ul><li>仅可重命名当前用户的容器</li><li>不能与已有容器同名</li></ul> |

## 典型使用流程

以下示例展示完整的容器开发工作流：

```bash
# 1. 直接用您的现网账号登录设备
# UID ≥ 1000 且具备交互式 shell 的账号，装机时已自动加入 boxusers 组

# 2. 启动开发容器
box-run --name mydev box-dev:0.1

# 3. 进入容器
box-exec -it mydev -- bash

# 4. 在容器内做开发
pwd                          # /workspace（自动挂载到您的 ~/box/workspace）
python3 --version
pip install requests

# 5. 退出容器并保存环境
exit
box-commit mydev myenv:1     # 自由命名

# 6. 用环境镜像启动新容器（直接以镜像名启动，与 docker run 一致）
box-run --name dev2 myenv:1
box-exec dev2 -- python3 -c "import requests; print(requests.__version__)"

# 7. 清理
box-stop dev2 && box-rm dev2
box-stop mydev && box-rm mydev
```

跨设备分发镜像的流程：

```bash
# 设备 A：导出镜像
box-save my-image:1
# -> ~/box/exports/my-image_1.tar
# （命令回显为软链接指向的实际路径，如 /open_app/workspaces/alice/box/exports/my-image_1.tar）

# 将文件拷贝到设备 B（目标路径需替换为设备 B 上对应用户的 home 目录）
scp ~/box/exports/my-image_1.tar <bob>@deviceB:/home/<bob>/

# 设备 B：从任意可读路径加载镜像
box-load /home/<bob>/my-image_1.tar
# -> 镜像 my-image:1 已加载至设备 B

# 设备 B：直接使用（以镜像名启动）
box-run my-image:1
```

## 命令详解

### box-run

创建并启动一个新容器。

```bash
box-run [--name NAME] [-p PORT] [--gpu auto|none] [--gpus GPU_SPEC] [--device DEV] [--functionfs FFS_DIR] [--network host] <image>:<tag> [-- command [args ...]]
```

**参数说明**

| 参数 | 是否必须 | 说明 | 示例 |
| :-- | :-- | :-- | :-- |
| image | 是 | 镜像名称，必须带 tag，格式为 `<image>:<tag>`（官方 / box-commit / box-load / box-pull 产物均可） | box-dev:0.1 |
| --name | 否 | 容器名，未指定时自动生成。命名须符合规则（详见下方「容器命名规则」） | --name mydev |
| -p, --publish | 否 | 端口映射，host 与 container 同号，范围 20000-20100，只绑定 `127.0.0.1`。与 `--network host` 互斥 | -p 20080 |
| --gpu | 否 | GPU 模式（兼容老写法）：`auto`（默认）或 `none` | --gpu none |
| --gpus | 否 | docker 风格 GPU 完整语法透传（`all` / `none` / `device=0` / `count=N`） | --gpus all |
| --device | 否 | 透传 host 设备（可多次），须为 `/dev/` 下绝对路径的字符 / 块设备（详见下方「设备透传」） | --device /dev/ttyUSB0 |
| --functionfs | 否 | 透传 host FunctionFS（USB gadget）端点目录（可多次），专供 PSDK USB bulk 场景（详见下方「PSDK USB 透传说明」） | --functionfs /dev/usb-ffs/bulk2 |
| --network | 否 | 仅接受 `host`，让容器共享宿主机网络命名空间（`--net` 为等价别名）。不支持 bridge / none / 自定义网络 | --network host |

:::tip 说明：
- 工作目录自动挂载到容器内 `/workspace`（对应主机 `~/box/workspace`）。
- 容器资源上限（平台预置，不可通过命令行参数覆盖）

| 资源 | 限制值 |
|:---|:---|
| 内存 | 12 GB |
| CPU | 6 核 |
| 共享内存（SHM） | 1 GB |
| 进程数（PIDs） | 512 |
| 文件描述符（nofile） | 软 1024 / 硬 2048 |
| 用户进程数（nproc） | 1024 |

如业务需要更高资源上限，请联系设备运维调整 `box.conf` 配置。
:::

**容器命名规则**

通过 `--name` 指定的容器名须满足以下规则，否则将被拒绝：

- 必须以字母或数字开头。
- 后续字符可包含：字母（`a-z`、`A-Z`）、数字（`0-9`）、下划线（`_`）、点（`.`）、横杠（`-`）。
- 不能包含空格、冒号（`:`）、斜杠（`/`）、中文及 `@`、`#`、`$` 等特殊字符。
- 长度为 2-64 个字符。
- 容器名必须唯一，不能与已有容器重名。

| 类型 | 示例 |
|:---|:---|
| 合法 | `mydev`、`test-1`、`test_1`、`test.1`、`A123`、`my-app_v1.0` |
| 非法 | `-test`（以横杠开头）、`g`（长度不足）、`my:app`（含冒号）、`my/app`（含斜杠） |

**示例**

```bash
# 最简启动
box-run box-dev:0.1

# 指定容器名 + 端口映射
box-run --name web -p 20080 box-dpk:0.1

# 禁用 GPU
box-run --gpus none box-dev:0.1

# 透传设备 + GPU + 端口组合
box-run --device /dev/ttyACM0 --gpus all -p 20088 my-app:1

# 基于自定义环境镜像启动并执行命令（直接以镜像名启动）
box-run myenv:1 -- python3 main.py
```

**设备透传（`--device`）**

当容器内需要访问主机物理设备（如 USB-Serial、USB 摄像头、GPIO、I2C 等）时，通过 `--device` 参数将设备透传至容器。

```bash
# 透传单个设备
box-run --device /dev/ttyUSB0 my-image:1

# 透传多个设备（可重复指定）
box-run --device /dev/ttyACM0 --device /dev/bus/usb/001/004 my-psdk-app:1

# 设备 + GPU + 端口组合使用
box-run --device /dev/ttyACM0 --gpus all -p 20088 my-app:1
```

使用约束：

- 路径必须为 `/dev/` 下的绝对路径
- 必须为字符设备或块设备，普通文件和目录会被拒绝
- **黑名单设备**（防止容器误操作导致设备损坏，无法解除）：`/dev/mem`、`/dev/kmem`、`/dev/sd*`、`/dev/nvme*`、`/dev/disk*`、`/dev/loop*`、`/dev/kvm`、`/dev/port`
- symlink 路径会自动解析为真实路径后再校验，无法绕过黑名单
- 容器内对透传设备拥有默认读写权限，但无法在容器内派生新设备节点

**PSDK USB 透传说明（`--functionfs` + `--network host`）**

PSDK 的 USB bulk 方案（编译产物位于 `build-manifold3-usbbulk/`）走 USB gadget 的 FunctionFS 接口，透传方式与普通字符设备不同：

```bash
# PSDK USB bulk 容器（--network host 与 --functionfs 均为必需项）
box-run --name psdkdev --gpus none --network host \
        --functionfs /dev/usb-ffs/bulk2 \
        --functionfs /dev/usb-ffs/bulk3 \
        box-dev:0.1
```

运行 PSDK 程序前，请先确认可执行文件已存在于 workspace 内（容器仅可访问 `/workspace`，其他主机目录不可见）。若尚未编译，请先参考 <a href="../quick-demo.html#运行-demo" target="_blank">运行 Demo</a> 章节完成编译，或使用 `box-cp` 将已编译的产物拷入 `~/box/workspace/`：

```bash
# 确认程序存在（路径请按实际工程目录调整）
box-exec psdkdev -- ls -l /workspace/payload-sdk/build-manifold3-usbbulk/bin/

# 运行 PSDK 程序
box-exec psdkdev -- sh -c 'cd /workspace/payload-sdk && ./build-manifold3-usbbulk/bin/dji_sdk_demo_on_manifold3'
```

FunctionFS 端点须使用 `--functionfs` 透传，不可使用 `--device`：端点（`ep0` / `ep1` / `ep2`）为 ffs 文件系统上的普通文件节点，既非字符设备也非块设备，通过 `--device` 透传会被拒绝并提示 `not a char/block device`。该提示属正常校验结果，并非路径填写错误。

使用约束：

- 须传入 ffs **挂载点目录本身**（如 `/dev/usb-ffs/bulk2`），而非其下的 `ep0` / `ep1` / `ep2`。
- 路径不支持通配符，须逐个显式指定。
- 通道号由 PSDK 程序自身的端点配置决定。以 manifold3 USB bulk 方案为例，须同时透传 `bulk2` 与 `bulk3`，缺少任一通道均会导致 PSDK 初始化失败。当前设备可用的通道可通过 `ls -d /dev/usb-ffs/bulk*` 查看。
- `--network host` 为必需项，缺少时 PSDK 无法与主机侧服务建立通信。

:::warning PSDK USB 注意事项
- **请勿停止主机侧的 `usb_bulk_raw` 进程**，该进程需保持常驻；一旦停止，`/dev/usb-ffs/` 下的端点将立即消失，容器内 PSDK 随之无法工作。
- 主机侧与容器内的 PSDK 程序不可同时运行，同一时刻仅应存在一个 PSDK 客户端。
- 容器内 PSDK 启动后若日志出现大量 `Bad file descriptor`，通常是 `--functionfs` 或 `--network host` 未正确指定，请对照上方命令逐项检查。
:::

**host 网络（`--network host`）**

容器共享宿主机网络命名空间，网络视图与宿主机完全一致（可见 `usb0` 等宿主机网卡，可访问宿主机本地服务）。

```bash
# 使用宿主机网络
box-run --name hostnet --network host box-dev:0.1

# --net 是等价别名
box-run --name hostnet2 --net host box-dev:0.1
```

使用约束：

- 仅接受 `host`，`bridge` / `none` / 自定义网络名一律拒绝。
- 与 `-p` / `--publish` 互斥：host 网络下容器直接共享宿主机端口空间，无需也无法发布端口。
- 容器内进程可监听宿主机任意空闲端口，**不再受 20000-20100 端口段限制**，请自行避开系统服务端口（如 sshd / dockerd 及各系统服务），抢占将导致主机业务异常。
- 容器内 `ping` 可正常使用，与默认 bridge 网络下的容器一致。
- 仍不授予 `CAP_NET_ADMIN`，容器内无法修改宿主机网络配置。

**GPU 使用（Jetson 平台）**

妙算 3 搭载 Jetson Orin 平台，`box-run` 默认为容器启用 GPU，无需额外参数。

```bash
# 默认启用 GPU（以下三种写法等价）
box-run --name g1 --gpus all box-dev:0.1
box-run --name g2 --gpu auto box-dev:0.1
box-run --name g3 box-dev:0.1

# 显式禁用 GPU（仅运行 CPU 业务时使用）
box-run --name g4 --gpus none box-dev:0.1

# 指定 GPU 能力集
box-run --name g5 --gpus 'all,"capabilities=video,compute"' box-dev:0.1
```

容器内使用 CUDA：

```bash
# 1. 拉完整镜像
box-pull nvcr.io/nvidia/l4t-pytorch:r35.2.1-pth2.0-py3

# 2. 后台启动容器
box-run --name torch-cuda --gpus all nvcr.io/nvidia/l4t-pytorch:r35.2.1-pth2.0-py3

# 3. 进入容器交互式 shell（本地 ssh 具备 TTY 时可用 -it；无 TTY 时仅可用 -i）
box-exec -it torch-cuda -- bash

# 4. 容器内验证 CUDA
python3 - <<'PY'
import torch
print("torch:", torch.__version__)
print("cuda:", torch.cuda.is_available())
print("device:", torch.cuda.get_device_name(0) if torch.cuda.is_available() else "No CUDA")
PY
```

**常见提示与含义**

| 现象 | 含义 |
|:---|:---|
| `[box-run] note: GPU 已请求，但 docker daemon 未启用 nvidia runtime` | 设备未启用 GPU 运行时，容器仍可启动但无法使用 GPU。若为纯 CPU 业务，添加 `--gpus none` 可抑制此提示；若需要 GPU 请联系运维 |
| `GR3D_FREQ 0%@0` | GPU 当前处于空闲状态，属正常现象 |

### box-load

从 tar 文件加载镜像。

```bash
box-load <file_path>                   # 默认保留 tar 内原镜像名
box-load <file_path> --as <repo>:<tag> # 显式指定镜像新名
```

**参数说明**

| 参数 | 是否必须 | 说明 | 示例 |
| :-- | :-- | :-- | :-- |
| file_path | 是 | tar 文件路径，须为当前用户可读；可放在 `~/box/imports/`（scp 友好），也可为任意当前用户可读路径 | ~/box/imports/my_env.tar |
| --as | 否 | 显式指定加载后的镜像名（默认保留 tar 内原名） | --as my-env:1 |

镜像加载需满足以下约束：

- 文件必须当前用户可读（平台以当前用户身份校验可读性，拒绝越权读取其他用户文件）。
- 文件必须为 docker save 格式的 tar（含 manifest.json 元数据）。
- 默认接受压缩 tar。
- tar 层数上限默认为 256 层（可由管理员通过 `box.conf` `IMPORT_MAX_LAYERS` 调整）。PyTorch/CUDA 完整镜像通常 30-50 层，不超此限。
- tar 内不得含设备节点 / fifo / socket / 绝对路径 / `..` 路径穿越。
- 加载后镜像名默认保留 tar 内原名，`--as` 可显式改名。

**示例**

```bash
# 从 imports 目录加载（推荐位置，scp 友好）
box-load ~/box/imports/my_env.tar

# 从任意可读路径加载
box-load /tmp/nginx.tar
box-load /home/alice/local-build.tar.gz  # 接受压缩 tar（建议使用绝对路径）

# 加载并改名
box-load /tmp/nginx.tar --as my-nginx:v1
```

## 使用限制

### 不提供的 docker 命令与替代做法

以下 docker 子命令在本平台不提供对应的 box 命令：

| docker 命令 | 替代做法 |
|:---|:---|
| docker push / login / logout / search | 设备不主动管控 registry 凭证；若需推送请使用自有 docker 凭证在外部环境完成 |
| docker build / docker builder | 通过 `box-run` 进入容器手动配置环境，再通过 `box-commit` 保存为镜像 |
| docker import | 用 `box-load`（走 `docker load` 协议，带镜像元数据校验） |
| docker export | 用 `box-save`（镜像粒度导出） |
| docker create | `box-run` 已合并创建与启动 |
| docker info / version / system df | docker / 内核版本见 `BUILD_INFO.txt` / `ENV_INFO.txt`；镜像、容器看 `box-images` + `box-ps -a` |
| docker network * / docker volume * | 网络走默认 bridge + 单端口 `-p` 透传，或使用 `--network host` 共享宿主机网络；数据走 `~/box/workspace`（自动挂载） |
| docker port | `box-ps` PORTS 列 + `box-inspect` 已覆盖 |
| docker events / update / attach | `attach` 用 `box-exec -it` 替代 |
| docker system prune / container prune / image prune | 用 `box-rmi` 单独清理镜像 |
| docker plugin / compose / swarm / node / service / secret / config / context / buildx / trust / manifest / stack / checkpoint | 受控环境不引入这些子系统 |

### 常见被拒绝的操作

下列操作平台不接受，会被拒绝执行：

```bash
docker xxx                        # permission denied（请用 box-*）
```
