## Overview

This guide explains how to build an automated illegal parking inspection system using Manifold 3 and PSDK. The system flies a drone along a preset waypoint mission, uses onboard AI to detect illegally parked vehicles in real time, and autonomously approaches targets for evidence collection.

This case study integrates several core PSDK capabilities:

- **Liveview**: Acquire real-time camera streams and decode them into images
- **AI Inference Label Push**: Overlay detection results onto Pilot App
- **Flight Control**: Waypoint missions, FlyTo, Point of Interest (POI) orbit
- **Camera Management**: Tap-to-zoom, photo capture for evidence

For the complete project source code of this case study, see the <a href="https://terra-1-g.djicdn.com/71a7d383e71a4fb8887a310eb746b47f/psdk/%E6%9C%80%E4%BD%B3%E5%AE%9E%E8%B7%B5Demo/Matrice%20400-parking-monitor-src-v01.00.00.15.tar.gz" target="_blank" rel="noopener noreferrer">sample project</a>.

### Workflow Details

#### Phase 1: System Initialization

1. Initialize all PSDK modules (Liveview, Flight Control, Camera Management, etc.)
2. Load the YOLOv5 TensorRT inference engine
3. Register AI detection label list

#### Phase 2: Send and Start Mission

1. Send waypoint mission via Pilot
2. Wait for waypoint mission to start

#### Phase 3: Cruise Detection

1. Subscribe to H30T Wide video stream and continuously execute AI inference
2. Check if the waypoint mission has ended; if so, clean up resources and exit
3. Determine if a vehicle target is detected; if not, continue patrol and inference
4. When a vehicle target is detected, enter the evidence collection phase

#### Phase 4: Approach and Evidence Collection

1. **Pause Mission** — Laser-point each target to obtain vehicle coordinates
2. **Tap-to-Zoom** — H30T Zoom camera locks onto the target
3. **FlyTo Approach** — Fly to approximately 10m from the target
4. **POI Orbit** — Execute an orbit around the target, capturing photos from multiple angles
5. **License Plate Recognition** — Subscribe to Zoom images and identify the license plate
6. If unprocessed targets remain, continue executing single target processing

#### Phase 5: Resume Mission

1. After evidence collection, resume the mission and continue area recheck
2. After all waypoints are completed, clean up resources and exit

### Build Steps

1. Upload the deployment source code to Manifold 3 `/open_app/` directory
2. Extract and enter the directory
3. Compile:

```bash
cd /open_app/yolov5_deploy
mkdir build && cd build
cmake ..
make -j$(nproc)
```

After compilation, the `build` directory will contain:

| File | Description |
|------|-------------|
| `libyolo_trt.so` | YOLOv5 inference shared library, ready for PSDK integration |
| `yolo_test` | Model conversion and testing tool |

### Core Features

- **Model Conversion**: Convert PyTorch weights to TensorRT inference engines
- **Performance Testing**: Verify model detection performance with test tools
- **Integration Interface**: Simplified YOLOv5 integration into PSDK projects

### Custom Model Training

Train models on a PC or server using the official YOLOv5 project. It is recommended to use drone-perspective datasets such as VisDrone, which provides significantly better detection performance compared to general-purpose models trained on COCO.

**Example**: Training a drone-perspective object detection model using VisDrone dataset in a Kaggle environment:


### Weight File Conversion

After training, convert the `.pt` weights into an intermediate format usable by TensorRT. Two approaches are available:

#### Option A: Convert to .wts File

1. Upload `best.pt` to Manifold 3
2. Create a `gen_wts.py` script with the following content:

```python
#!/usr/bin/env python3
import sys
import struct
import argparse

import numpy as np
import numpy.core
import numpy.core.multiarray
sys.modules.setdefault('numpy._core', np.core)
sys.modules.setdefault('numpy._core.multiarray', numpy.core.multiarray)

import torch

def main():
    parser = argparse.ArgumentParser()
    parser.add_argument('--input', '-i', default='best.pt', help='Input .pt file')
    parser.add_argument('--output', '-o', default='best.wts', help='Output .wts file')
    parser.add_argument('--no-convert-anchors', action='store_true',
                        help='Skip anchor conversion (not recommended)')
    args = parser.parse_args()

    pt_file = args.input
    wts_file = args.output

    ckpt = torch.load(pt_file, map_location='cpu', weights_only=False)
    model = ckpt['model'].float().eval()

    m = model.model[-1]
    strides = m.stride.cpu().numpy()
    anchors = m.anchors.clone().cpu().numpy()

    print(f"Strides: {strides}")
    print(f"Original anchors (max={anchors.max():.4f}, shape={anchors.shape})")

    state_dict = model.state_dict()
    anchor_key = next((k for k in state_dict.keys()
                       if 'anchors' in k and 'anchor_grid' not in k), None)

    if anchor_key is None:
        print("Warning: No anchor key found in model")
    elif args.no_convert_anchors:
        print("Skipping anchor conversion (--no-convert-anchors)")
    else:
        pixel_anchors = anchors.copy()
        for i in range(len(strides)):
            pixel_anchors[i] *= strides[i]

        state_dict[anchor_key] = torch.tensor(pixel_anchors).float()
        model.load_state_dict(state_dict, strict=False)
        print(f"Anchors converted to pixel units: max={pixel_anchors.max():.2f}")

    with open(wts_file, 'w') as f:
        f.write(f"{len(state_dict)}\n")
        for k, v in state_dict.items():
            vr = v.reshape(-1).cpu().numpy()
            f.write(f"{k} {len(vr)}")
            for vv in vr:
                f.write(f" {struct.pack('>f', float(vv)).hex()}")
            f.write("\n")

    print(f"Done: {wts_file}")

if __name__ == '__main__':
    main()
```

3. Run the conversion:

```bash
python3 gen_wts.py
```

After completion, a `best.wts` file will be generated in the current directory.

#### Option B: Convert to .onnx File (Recommended on Ubuntu)

1. Clone the YOLOv5 official repository:

```bash
git clone https://github.com/ultralytics/yolov5.git
cd yolov5
```

2. Install dependencies:

```bash
pip3 install -r requirements.txt
pip3 install onnx onnxslim
```

3. Place `best.pt` in the `yolov5` directory and run the export:

```bash
python3 export.py \
  --weights best.pt \
  --include onnx \
  --imgsz 640 \
  --opset 12 \
  --simplify
```

After completion, a `best.onnx` file will be generated.

### Generate TensorRT Inference Engine

Use the `yolo_test` tool to convert weight files into a TensorRT inference engine.

**From .wts file:**

```bash
./yolo_test -e best.wts best.engine s 10
```

**From .onnx file:**

```bash
./yolo_test -eo best.onnx best.engine 10
```

### Inference Verification

1. Set up the test environment:

```bash
mkdir test
# Place test images in the test directory
# Create a visdrone.names file (containing target classes)
```

2. Run the test:

```bash
./yolo_test -d best.engine visdrone.names ./test
```

After completion:
- The terminal outputs detection results and inference latency
- The `output` directory contains test images with detection bounding boxes drawn

## PSDK Integration

Manifold 3 supports acquiring 1080p/4K camera streams from the drone via PSDK, as well as RGB/NV12 format image data after NVIDIA hardware decoding. It is recommended to use the decoded images directly for AI inference.

### 1. Initialize Liveview Module

```cpp
T_DjiReturnCode DjiLiveview_Init(void);
```

### 2. Register AI Detection Label List

```cpp
T_DjiReturnCode DjiLiveview_RegUserAiTargetLableList(
    uint8_t lableCount,
    const char *labels[]
);
```

### 3. Subscribe to Image Stream and Run Inference

```cpp
T_DjiReturnCode DjiLiveview_StartImageStream(
    E_DjiLiveViewCameraPosition position,
    E_DjiLiveViewCameraSource source,
    Callback function
);
```

In the callback, receive NVIDIA hardware-decoded RGB/NV12 images and invoke the YOLOv5 inference library for object detection.

### 4. Push Detection Results

```cpp
T_DjiReturnCode DjiLiveview_SendAiMetaToPilot(
    T_DjiLiveViewStandardMetaData *metaData
);
```

Send bounding boxes, confidence scores, and other detection results to the flight controller for real-time rendering in Pilot App.

:::warning Note
The AI label push feature requires the application to be launched as a DPK application to take effect.
:::
