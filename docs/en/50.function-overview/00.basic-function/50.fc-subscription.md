## Overview

The data subscription function of PSDK supports payload devices to subscribe to the data information pushed by the aircraft, enabling a wider range of applications.

## API Overview

The following table lists the main interfaces and callback functions for the data subscription feature.

:::tip Note:
Interfaces with `()` in the table are actively called interfaces, while those without `()` are callback functions.
:::

<table class="col-1-left col-2-left col-3-left">
  <thead>
    <tr>
      <th>Category</th>
      <th>Interface / Callback</th>
      <th>Description</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td rowspan="2"><b>Initialization & Deinitialization</b></td>
      <td>DjiFcSubscription_Init()</td>
      <td>Initialize the data subscription module</td>
    </tr>
    <tr>
      <td>DjiFcSubscription_DeInit()</td>
      <td>Deinitialize the data subscription module and release system resources</td>
    </tr>
    <tr>
      <td rowspan="4"><b>Message Subscription</b></td>
      <td>DjiFcSubscription_SubscribeTopic()</td>
      <td>Subscribe to a specified data topic with configurable frequency and callback function</td>
    </tr>
    <tr>
      <td>DjiFcSubscription_UnSubscribeTopic()</td>
      <td>Unsubscribe from a specified data topic; must be unsubscribed in subscription order</td>
    </tr>
    <tr>
      <td>DjiFcSubscription_GetLatestValueOfTopic()</td>
      <td>Get the latest data value and corresponding timestamp of a subscribed topic</td>
    </tr>
    <tr>
      <td>DjiReceiveDataOfTopicCallback</td>
      <td>Callback function prototype for receiving subscription data, automatically triggered by the SDK when data is received</td>
    </tr>
  </tbody>
</table>

## Basic Concepts

### Message Subscription

Various components on the drone will generate a large amount of data information in real time according to the actual flight status of the drone and will be pushed to other modules by the drone. The user can specify the data information to be subscribed by using the payload device with the message subscription function.

### Subscription Rules
### Subscription Rules
* The supported frequencies of subscription topics are 1Hz, 5Hz, 10Hz, 50Hz, 100Hz, 200Hz and 400Hz. The frequency range of each topic is different. The same topic can be subscribed multiple times at different frequencies, and each frequency's callback will be triggered independently.
* When specifying the subscription frequency, the subscription frequency of any parameter cannot be less than or equal to 0, and the sum of the data lengths of topics with the same subscription frequency must be less than or equal to 242.
* The subscription frequency can only be a divisor of the "maximum subscription frequency".
* The total number of distinct subscription frequency types across all subscribed topics must be less than or equal to 4.

:::warning Note:
 When using the simulator in DJI Assistant 2 to simulate the working state of the payload device, the simulator will **not be able to obtain** sensor raw data such as GPS information and RTK information, but developers can subscribe to fused data such as fused position, fused altitude, or relative altitude.
:::

## Implementation

PSDK supports subscription to the data information pushed by the aircraft through two methods: registration callback and interface call.

:::tip Note:
 Using the subscription feature, you will receive the subscription item data along with the aircraft system time when the data was generated. This time is **currently not supported** for synchronization with the time on the payload device. For Matrice 300 and Matrice 350 models, the aircraft time is obtained; for other models, the PSDK local time is obtained.
:::

:::warning Note:
 The following code samples are provided as reference examples to help developers understand the calling workflow and implementation approach of each feature. Developers should adapt and adjust based on the actual hardware characteristics and application scenarios of their own payload devices.
:::

### Initialization

If a payload developed with PSDK needs to subscribe to the status information on the aircraft, it needs to call `DjiFcSubscription_Init()` to initialize the message subscription module.

```c
djiStat = DjiFcSubscription_Init();
if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("init data subscription module error.");
    return DJI_ERROR_SYSTEM_MODULE_CODE_UNKNOWN;
}
```

### Message Subscription

Subscribe to a specified data topic via `DjiFcSubscription_SubscribeTopic()`, with configurable subscription frequency and callback function. When the data of a subscription topic is no longer needed, you can unsubscribe via `DjiFcSubscription_UnSubscribeTopic()`.

<!-- Data subscription mode flow diagram -->

      <img src="https://terra-1-g.djicdn.com/71a7d383e71a4fb8887a310eb746b47f/psdk/function-overview/info-management/fc_subscription_mode_2_en.svg" width="40%" alt="Data Subscription Mode Flow"/></span></p>

PSDK supports two subscription modes:
- **Callback mode**: Specify a callback function in `DjiFcSubscription_SubscribeTopic()`. The SDK automatically calls the callback to push data when data is received, suitable for scenarios requiring high real-time performance.
- **Polling mode**: Set the callback parameter to NULL and actively call `DjiFcSubscription_GetLatestValueOfTopic()` in the business thread to get the latest data, suitable for on-demand retrieval scenarios.

:::tip Note:
 When using the subscription feature to subscribe to data on the aircraft, the subscription frequency can only be a divisor of the "maximum subscription frequency".
:::

**Callback Mode Subscription**

Subscribe to the aircraft attitude quaternion at 1Hz with a specified callback function:

```c
djiStat = DjiFcSubscription_SubscribeTopic(DJI_FC_SUBSCRIPTION_TOPIC_QUATERNION, DJI_DATA_SUBSCRIPTION_TOPIC_1_HZ,
                                           DjiTest_FcSubscriptionReceiveQuaternionCallback);
if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Subscribe topic quaternion error.");
    return DJI_ERROR_SYSTEM_MODULE_CODE_UNKNOWN;
}
```

**Polling Mode Subscription**

Start subscription without callback mode by setting the callback parameter to NULL:

```c
djiStat = DjiFcSubscription_SubscribeTopic(DJI_FC_SUBSCRIPTION_TOPIC_VELOCITY, DJI_DATA_SUBSCRIPTION_TOPIC_1_HZ,
                                               NULL);
if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Subscribe topic velocity error.");
    return DJI_ERROR_SYSTEM_MODULE_CODE_UNKNOWN;
}

djiStat = DjiFcSubscription_SubscribeTopic(DJI_FC_SUBSCRIPTION_TOPIC_GPS_POSITION, DJI_DATA_SUBSCRIPTION_TOPIC_1_HZ,
                                               NULL);
if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
  	USER_LOG_ERROR("Subscribe topic gps position error.");
    return DJI_ERROR_SYSTEM_MODULE_CODE_UNKNOWN;
}
```

**Unsubscribe**

:::warning Note:
Unsubscription must be performed in the order of subscription, following a FIFO (First In, First Out) mechanism - the topic subscribed first must be unsubscribed first. For example, if topics A, B, and C were subscribed in that order, they must be unsubscribed in the order A -> B -> C. You cannot skip A and directly unsubscribe B or C.
:::

```c
// Assuming subscription order is QUATERNION -> VELOCITY -> GPS_POSITION
// Unsubscription must follow the same order
djiStat = DjiFcSubscription_UnSubscribeTopic(DJI_FC_SUBSCRIPTION_TOPIC_QUATERNION);
if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Unsubscribe topic quaternion error.");
}

djiStat = DjiFcSubscription_UnSubscribeTopic(DJI_FC_SUBSCRIPTION_TOPIC_VELOCITY);
if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Unsubscribe topic velocity error.");
}

djiStat = DjiFcSubscription_UnSubscribeTopic(DJI_FC_SUBSCRIPTION_TOPIC_GPS_POSITION);
if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Unsubscribe topic gps position error.");
}
```

**Retrieve Data via Callback**

PSDK supports two methods for retrieving subscription data: receiving data in real-time via callback functions, or actively retrieving data via the polling interface.

Receive the information pushed by the aircraft by constructing a callback function.

:::warning Note:
 To avoid memory corruption, the data address type must be cast to the pointer type in the subscription item data structure.
:::

```c
static T_DjiReturnCode DjiTest_FcSubscriptionReceiveQuaternionCallback(const uint8_t *data, uint16_t dataSize, const T_DjiDataTimestamp *timestamp)
{
    T_DjiFcSubscriptionQuaternion *quaternion = (T_DjiFcSubscriptionQuaternion *) data;
    dji_f64_t pitch, yaw, roll;

    USER_UTIL_UNUSED(dataSize);

    pitch = (dji_f64_t) asinf(-2 * quaternion->q1 * quaternion->q3 + 2 * quaternion->q0 * quaternion->q2) * 57.3;
    roll = (dji_f64_t) atan2f(2 * quaternion->q2 * quaternion->q3 + 2 * quaternion->q0 * quaternion->q1, -2 * quaternion->q1 * quaternion->q1 - 2 * quaternion->q2 * quaternion->q2 + 1) * 57.3;
    yaw = (dji_f64_t) atan2f(2 * quaternion->q1 * quaternion->q2 + 2 * quaternion->q0 * quaternion->q3, -2 * quaternion->q2 * quaternion->q2 - 2 * quaternion->q3 * quaternion->q3 + 1) * 57.3;

    if (s_userFcSubscriptionDataShow == true) {
        USER_LOG_INFO("receive quaternion data.");

        USER_LOG_INFO("timestamp: millisecond %u microsecond %u.", timestamp->millisecond,
                      timestamp->microsecond);
        USER_LOG_INFO("quaternion: %f %f %f %f.\r\n", quaternion->q0, quaternion->q1, quaternion->q2, quaternion->q3);
        USER_LOG_INFO("euler angles: pitch = %.2f roll = %.2f yaw = %.2f.", pitch, yaw, roll);
        DjiTest_WidgetLogAppend("pitch = %.2f roll = %.2f yaw = %.2f.", pitch, yaw, roll);
    }

    return DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS;
}
```

**Retrieve Data via Polling**

Retrieve the latest subscription item data and its corresponding time generated by the aircraft via `DjiFcSubscription_GetLatestValueOfTopic()`. The following code retrieves the latest flight velocity and GPS coordinates at 1Hz:

```c
djiStat = DjiFcSubscription_GetLatestValueOfTopic(DJI_FC_SUBSCRIPTION_TOPIC_VELOCITY,
                                                  (uint8_t *) &velocity,
                                                  sizeof(T_DjiFcSubscriptionVelocity),
                                                  &timestamp);
if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("get value of topic velocity error.");
} else {
    USER_LOG_INFO("velocity: x = %f y = %f z = %f healthFlag = %d.", velocity.data.x, velocity.data.y,
                  velocity.data.z, velocity.health);
}

djiStat = DjiFcSubscription_GetLatestValueOfTopic(DJI_FC_SUBSCRIPTION_TOPIC_GPS_POSITION,
                                                  (uint8_t *) &gpsPosition,
                                                  sizeof(T_DjiFcSubscriptionGpsPosition),
                                                  &timestamp);
if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("get value of topic gps position error.");
} else {
    USER_LOG_INFO("gps position: x = %d y = %d z = %d.", gpsPosition.x, gpsPosition.y, gpsPosition.z);
}
```
