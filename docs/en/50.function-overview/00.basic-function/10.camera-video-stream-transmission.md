## Overview
Using the video stream transmission control function provided by PSDK, the developer **needs to first implement** the function of obtaining the code stream of the video stream file, encode the video stream according to the H.264 encoding format, and call the specified interface to send the video stream data in combination with the video frame rate and other parameters. Users can obtain the real-time video data on the camera payload device by using DJI Pilot and the Mobile App developed based on MSDK.

:::tip Related References:
* Please refer to <a href="../../payload-quick-start/configure-the-hardware-environment/payload-develop-criterion.html#video-stream-transmission-standard" target="_blank" rel="noopener noreferrer">Video Standard</a> for the detailed description of the video stream format.
* Please refer to <a href="https://www.itu.int/rec/T-REC-H.264-201906-S/en">H.264 Code Streaming Standards</a> for related reference to H.264 standard code stream.
* The video streaming function is only supported by the camera payload device developed based on Linux.
* The STM32 + UDP streaming method is no longer supported or maintained on Matrice 400. Please use the Linux platform for video stream transmission development.
:::

## Basic Concepts

### Network Parameter Configuration

To use the video stream transmission function, you need to configure the network parameters of the payload device first. There are two methods:
* **Automatic Configuration (Recommended)**: Register the callback function for network parameter configuration through `DjiPlatform_RegHalNetworkHandler()`. The SDK will automatically complete the negotiation and setting of network parameters, and the payload device can use all functions related to the network port.
* **Manual Configuration**: Without registering the network callback function, the developer manually sets the network parameters (IP: `192.168.5.3`, Gateway: `192.168.5.1`, Subnet Mask: `255.255.255.0`). In this mode, **only the video stream transmission function can be used**, and other functions involving the network port will not be available.

### Video Stream Transmission Requirements

* The video stream must be encoded in H.264 encoding format
* The maximum frame length that can be sent by a camera payload device developed based on PSDK is 65K. If the frame length exceeds 65K, the frame needs to be split before sending
* To avoid blurred screen and green screen issues caused by other tasks blocking the video stream processing thread, please create a separate video stream processing thread

## Implementation

:::tip Note:
 The video stream transmission function requires development on the Linux platform.
:::

:::warning Caution:
 The following code is for reference only, intended to help developers understand the calling process and implementation approach of each function. Developers can adapt and adjust according to the actual hardware characteristics and application scenarios of their payload devices.
:::

### Set Video Stream Type (Optional)

Before calling `DjiCore_ApplicationStart()`, developers can set the video stream encoding format through `DjiPayloadCamera_SetVideoStreamType()`. PSDK supports two video stream types:

- **H264 Custom Format** (Default): The video stream bitrate needs to be dynamically adjusted based on the real-time bandwidth limit returned by `DjiPayloadCamera_GetVideoStreamState()`.
- **H264 DJI Format**: The video stream is re-encoded by the aircraft, no need to dynamically adjust the bitrate, but the bitrate cannot exceed 8Mbps.

:::warning Caution:
* This interface must be called before `DjiCore_ApplicationStart()`. The thread will block when called, with a maximum blocking time of 10s.
* If this interface is not called, H264 Custom format is used by default.
* If the video stream format is set to DJI H264 format, the data stream transmission function will not be available.
:::

```c
// Must be called before DjiCore_ApplicationStart()
returnCode = DjiPayloadCamera_SetVideoStreamType(DJI_CAMERA_VIDEO_STREAM_TYPE_H264_CUSTOM_FORMAT);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("set video stream type error: 0x%08llX.", returnCode);
    return returnCode;
}
```

### Configure Network Parameters

#### Set Network Parameters Automatically (Recommended)    
When automatically setting the network parameters, the developer must use the `DjiPlatform_RegHalNetworkHandler()` interface to register the callback function for setting the network parameters of the payload device.     

* Construct the callback function  

```c
T_DjiReturnCode HalNetWork_Init(const char *ipAddr, const char *netMask, T_DjiNetworkHandle *halObj)
{
    int32_t ret;
    char cmdStr[LINUX_CMD_STR_MAX_SIZE];

    if (ipAddr == NULL || netMask == NULL) {
        USER_LOG_ERROR("hal network config param error");
        return DJI_ERROR_SYSTEM_MODULE_CODE_INVALID_PARAMETER;
    }

    //Attention: need root permission to config ip addr and netmask.
    memset(cmdStr, 0, sizeof(cmdStr));

    snprintf(cmdStr, sizeof(cmdStr), "ifconfig %s up", LINUX_NETWORK_DEV);
    ret = system(cmdStr);
    if (ret != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
        USER_LOG_ERROR("Can't open the network."
                       "Probably the program not execute with root permission."
                       "Please use the root permission to execute the program.");
        return DJI_ERROR_SYSTEM_MODULE_CODE_SYSTEM_ERROR;
    }

    snprintf(cmdStr, sizeof(cmdStr), "ifconfig %s %s netmask %s", LINUX_NETWORK_DEV, ipAddr, netMask);
    ret = system(cmdStr);
    if (ret != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
        USER_LOG_ERROR("Can't config the ip address of network."
                       "Probably the program not execute with root permission."
                       "Please use the root permission to execute the program.");
        return DJI_ERROR_SYSTEM_MODULE_CODE_SYSTEM_ERROR;
    }

    return DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS;
}
```

* Register the callback function       
After registering the `DjiPlatform_RegHalNetworkHandler()` callback function, the user uses the `sudo` command (administrator privilege) to execute the program of the payload device, and realizes the automatic configuration of the network parameters of the payload device by obtaining the network configuration information negotiated between the drone and the payload device.       

:::tip Note:
 For Linux systems with the `network-manager` service, you need to delete all the configuration information of the `network-manager` service, otherwise the network parameters cannot be successfully configured.
:::

```c
    returnCode = DjiPlatform_RegHalNetworkHandler(&networkHandler);
    if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
        printf("register hal network handler error");
        return DJI_ERROR_SYSTEM_MODULE_CODE_SYSTEM_ERROR;
    }
```

#### Set Network Parameters Manually
When setting the network parameters of the camera payload device **manually**, the user **can only use the video stream transmission function, and other functions involving the use of the network port will not be available**.    
   * IP address: `192.168.5.3`
   * Gateway: `192.168.5.1`
   * Subnet mask: `255.255.255.0`

After the IP address is set, use the `ping` and `ifconfig` commands to view the network status between the camera payload device and the aircraft.

### Create Video Stream Processing Thread

To avoid blurred screen and green screen issues caused by other tasks blocking the video stream processing thread during video stream transmission, please create a separate video stream processing thread when using PSDK to develop a camera payload device.

```c
    returnCode = osalHandler->TaskCreate("user_camera_media_task", UserCameraMedia_SendVideoTask, 2048, NULL, &s_userSendVideoThread);
    if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
        USER_LOG_ERROR("user send video task create error.");
        return DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS;
    }
```

When the video stream processing thread is initialized, the thread state needs to be initialized first and memory space for caching video stream files needs to be requested from the camera payload device.

```c
    videoFilePath = osalHandler->Malloc(DJI_FILE_PATH_SIZE_MAX);
    if (videoFilePath == NULL) {
        USER_LOG_ERROR("malloc memory for video file path fail.");
        exit(1);
    }

    transcodedFilePath = osalHandler->Malloc(DJI_FILE_PATH_SIZE_MAX);
    if (transcodedFilePath == NULL) {
        USER_LOG_ERROR("malloc memory for transcoded file path fail.");
        exit(1);
    }

    frameInfo = osalHandler->Malloc(VIDEO_FRAME_MAX_COUNT * sizeof(T_TestPayloadCameraVideoFrameInfo));
    if (frameInfo == NULL) {
        USER_LOG_ERROR("malloc memory for frame info fail.");
        exit(1);
    }
    memset(frameInfo, 0, VIDEO_FRAME_MAX_COUNT * sizeof(T_TestPayloadCameraVideoFrameInfo));
```

:::tip Compatibility Notes:
* PSDK V2.0.0 and above supports interfaces for video stream sending and video stream status information acquisition. Developers need to call the video stream sending interface according to the video stream status (bit rate and other information) to send a video stream that conforms to the encoding specification.
* The sample program of PSDK V1.5.x video stream can be used with the program of PSDK V2.0.0 and above. When using it, please do not register the callback function `halNetWorkHandler()`, and manually set the IP of the payload device. Otherwise the example will not work.
:::

### Get Video Stream File Information
Before sending a video stream file, a camera payload device developed with PSDK must read the local H.264 file of the camera payload device to obtain the information of the video stream file.

* Read the local H.264 file of the camera payload device       
After the user specifies the **exact** path of the H.264 file on the payload device, the camera payload device developed based on PSDK opens the video stream file specified by the user through the system interface.

```c
returnCode = DjiUserUtil_GetCurrentFileDirPath(__FILE__, DJI_FILE_PATH_SIZE_MAX, curFileDirPath);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Get file current path error, stat = 0x%08llX", returnCode);
    exit(1);
}
snprintf(tempPath, DJI_FILE_PATH_SIZE_MAX, "%smedia_file/PSDK_0005.h264", curFileDirPath);

videoFilePath = osalHandler->Malloc(DJI_FILE_PATH_SIZE_MAX);
if (videoFilePath == NULL) {
    USER_LOG_ERROR("malloc memory for video file path fail.");
    exit(1);
}

fpFile = fopen(transcodedFilePath, "rb+");
if (fpFile == NULL) {
    USER_LOG_ERROR("open video file fail.");
    continue;
}
```

* Get H.264 file information        
  The camera payload device developed based on PSDK uses ffmpeg to read the frame rate, frame information and total number of frames of the specified H.264 file.
  * Frame rate: The number of frames that the camera payload device can send in 1s
  * Frame information: The starting position of a frame in the H.264 video stream file and the length of the frame

```c
// video send preprocess
returnCode = DjiPlayback_VideoFileTranscode(videoFilePath, "h264", transcodedFilePath,
                                            DJI_FILE_PATH_SIZE_MAX);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("transcode video file error: 0x%08llX.", returnCode);
    continue;
}

returnCode = DjiPlayback_GetFrameRateOfVideoFile(transcodedFilePath, &frameRate);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("get frame rate of video error: 0x%08llX.", returnCode);
    continue;
}

returnCode = DjiPlayback_GetFrameInfoOfVideoFile(transcodedFilePath, frameInfo, VIDEO_FRAME_MAX_COUNT, &frameCount);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("get frame info of video error: 0x%08llX.", returnCode);
    continue;
}

returnCode = DjiPlayback_GetFrameNumberByTime(frameInfo, frameCount, &frameNumber,
                                              startTimeMs);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("get start frame number error: 0x%08llX.", returnCode);
    continue;
}

if (fpFile != NULL)
    fclose(fpFile);
```

### Video Stream File Parsing
After the camera payload device developed based on PSDK obtains the information of the video stream file, it will parse the content of the video stream file and identify the frame header of the video stream file.

```c
dataBuffer = calloc(frameBufSize, 1);
if (dataBuffer == NULL) {
    USER_LOG_ERROR("malloc fail.");
    goto free;
}

ret = fseek(fpFile, frameInfo[frameNumber].positionInFile, SEEK_SET);
if (ret != 0) {
    USER_LOG_ERROR("fseek fail.");
    goto free;
}

dataLength = fread(dataBuffer, 1, frameInfo[frameNumber].size, fpFile);
if (dataLength != frameInfo[frameNumber].size) {
    USER_LOG_ERROR("read data from video file error.");
} else {
    USER_LOG_DEBUG("read data from video file success, len = %d B\r\n", dataLength);
}
```

After using DJI Pilot or a Mobile App developed based on MSDK to send a video streaming command to the camera payload device, the Mobile App will be able to receive and loop the media files in the camera payload device.

### Video Stream Status Monitoring
The camera payload device developed with PSDK can obtain the status information of video stream sending (real-time bandwidth limit, bandwidth usage, busy state, etc.), which is convenient for users to adjust the frame rate of the video transmitted by the video stream transmission module.

```c
returnCode = DjiPayloadCamera_GetVideoStreamState(&videoStreamState);
if (returnCode == DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_DEBUG(
        "video stream state: realtimeBandwidthLimit: %d, realtimeBandwidthBeforeFlowController: %d, realtimeBandwidthAfterFlowController:%d busyState: %d.",
        videoStreamState.realtimeBandwidthLimit, videoStreamState.realtimeBandwidthBeforeFlowController,
        videoStreamState.realtimeBandwidthAfterFlowController,
        videoStreamState.busyState);
} else {
    USER_LOG_ERROR("get video stream state error.");
}
```
