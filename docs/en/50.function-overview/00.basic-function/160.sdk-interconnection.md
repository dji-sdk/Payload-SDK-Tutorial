## Overview

"Payload developed based on PSDK (payload device)", "Payload developed based on PSDK (onboard application)", and "Mobile App developed based on MSDK" can communicate with each other. For example, users send control commands from the Mobile App to the aircraft to control the payload device to execute specified tasks. The onboard application controls the payload device to perform required actions and sends status information to the Mobile App. The payload device sends data such as video streams or files to the Mobile App and onboard application.

Using the SDK interconnection function, developers can:
* Dynamically create the required transmission channels on demand
* According to business needs, create a channel to transmit the data of the specified business
* Full-duplex communication, data sending and receiving synchronization

## Basic Concepts

### Client and Server

* **Client**: The end that initiates the channel connection according to the specified channel ID.
* **Server**: The end that creates a channel and specifies the channel ID according to the user's actual requirements.

When MSDK communicates with PSDK payload devices, MSDK can only act as a client, and the PSDK payload device acts as a server. When PSDK payload devices communicate with each other, both PSDK payload (payload device) and PSDK payload (onboard application) can act as clients.

### Transfer Method

* **Reliable Transmission**<br/>
  DJI SDK internally uses mechanisms such as packet loss retransmission, timeout retransmission, and error checking to ensure that data sent and received between different SDKs is accurate and reliable.
  * Data reliability: Uses a verification function to check the correctness of transmitted data when sending and receiving, and uses encryption algorithms to encrypt transmitted data to ensure security.
  * Transmission reliability: Has a timer and ACK mechanism, automatically retransmits data after timeout to prevent accidental data loss. The sender numbers the data, and the receiver can rearrange out-of-order data to ensure transmission reliability.
* **Unreliable Transmission**<br/>
  When data is transmitted in an unreliable transmission method, data can be transmitted at a faster speed between onboard applications and devices, but reliable transmission of data cannot be guaranteed.

### Object Specification

The interconnection function of the DJI SDK can accurately specify the device or module that needs to be communicated on the aircraft through the device type and device slot.

* **Device type**: Used to identify the identity and type of the peer end and distinguish data transmission objects, including MSDK, PSDK (onboard application) and PSDK (payload device).
* **Device slot**: DJI's aircraft support various expansion methods to access payload devices and onboard applications, and different slots can be used to distinguish the current location of the Mobile App, payload device and onboard application.
* **Channel ID**: Used to distinguish different channels on the same device. Developers can specify IDs for channels when creating them.

:::tip Note:
* Only payload devices and onboard applications developed based on PSDK need to specify a channel ID for the created channel when using the data transmission function.
* Developers can specify a channel ID for the created channel when creating a channel according to actual usage requirements, and a maximum of 65535 channels can be set.
:::

### Channel Management

DJI SDK provides communication management capabilities for the interconnection function, so developers do not need to focus on the underlying working logic:

* **Link management**: Manage link access, shutdown, destruction, reconnection and congestion management, etc.
* **Data management**: Data forwarding, data reading and writing, flow control, data verification, out-of-order rearrangement and packet loss retransmission, etc.

### Channel Bandwidth

:::warning Caution:
The following data is for reference only. Actual results may vary depending on real-world testing.
:::

* The maximum rate of MSDK upstream (sending data to server) reliable/unreliable transmission is generally **24-48 Kbps**. The upper limit of bandwidth depends on the actual wireless link conditions.
* The maximum rate of MSDK downstream (receiving data from server) reliable transmission is **16Mbps**. The maximum unreliable transmission rate is **20Mbps**.
* For data transmission between PSDK onboard application and PSDK payload device, the maximum reliable transmission rate is **24Mbps**, and the maximum unreliable transmission rate is **30Mbps**.

## Implementation

:::warning Caution:
The following code is for reference only, intended to help developers understand the calling process and implementation approach of each function. Developers can adapt and adjust according to the actual hardware characteristics and application scenarios of their payload devices.
:::

### PSDK Side

Only payload devices developed on the Linux platform support developing the interconnection function based on PSDK.

#### Initialization and Creation

Before using the SDK interconnection function, you need to initialize the MOP channel module first, then create a channel handle. When creating a channel, you need to specify the transmission type: reliable transmission or unreliable transmission.

```c
// Initialize the MOP channel module
T_DjiReturnCode returnCode = DjiMopChannel_Init();
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("MOP channel init error, stat:0x%08llX.", returnCode);
    return returnCode;
}

// Create a channel handle (choose reliable or unreliable transmission)
T_DjiMopChannelHandle channelHandle;
returnCode = DjiMopChannel_Create(&channelHandle, DJI_MOP_CHANNEL_TRANS_RELIABLE);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("MOP channel create error, stat:0x%08llX.", returnCode);
    return returnCode;
}
```

#### Server Connection

When the payload device developed based on PSDK acts as a server, it needs to first bind the channel ID to the created channel handle, then call `DjiMopChannel_Accept()` to block and wait for client connection. To support establishing connections with multiple clients simultaneously, `DjiMopChannel_Accept()` returns a new `outChannelHandle` handle for subsequent data sending and receiving.

:::tip Note:
`DjiMopChannel_Accept()` is a blocking interface. It is recommended to call it in a separate thread.
:::

```c
// Bind channel ID
REBIND:
returnCode = DjiMopChannel_Bind(channelHandle, 49152);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("MOP bind channel error: 0x%08llX", returnCode);
    osalHandler->TaskSleepMs(3000);
    goto REBIND;
}

// Block and wait for client connection
T_DjiMopChannelHandle outChannelHandle;
REACCEPT:
returnCode = DjiMopChannel_Accept(channelHandle, &outChannelHandle);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_WARN("MOP accept channel error: 0x%08llX", returnCode);
    osalHandler->TaskSleepMs(3000);
    goto REACCEPT;
}
USER_LOG_INFO("MOP channel connected.");
```

#### Client Connection

When the payload device developed based on PSDK acts as a client (e.g., in PSDK-to-PSDK interconnection scenarios), use `DjiMopChannel_Connect()` to actively connect to the server at the specified address and channel ID.

:::tip Note:
`DjiMopChannel_Connect()` is a blocking interface. It is recommended to call it in a separate thread.
:::

```c
// Connect to the server (specify channel address and channel ID)
T_DjiReturnCode returnCode = DjiMopChannel_Connect(channelHandle,
                                                    DJI_CHANNEL_ADDRESS_PAYLOAD_PORT_NO1,
                                                    49152);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("MOP connect error: 0x%08llX", returnCode);
    return returnCode;
}
USER_LOG_INFO("MOP channel connected to server.");
```

#### Data Send/Receive

After the channel connection is established, data can be sent and received through `DjiMopChannel_SendData()` and `DjiMopChannel_RecvData()`. The server uses the `outChannelHandle` returned by `DjiMopChannel_Accept()` for sending and receiving; the client directly uses the created `channelHandle` for sending and receiving.

:::tip Note:
`DjiMopChannel_RecvData()` is a blocking interface. It is recommended to call it in a separate thread.
:::

```c
// Receive data
uint8_t recvBuf[100 * 1024];
uint32_t realLen = 0;
returnCode = DjiMopChannel_RecvData(outChannelHandle, recvBuf, sizeof(recvBuf), &realLen);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    if (returnCode == DJI_ERROR_MOP_CHANNEL_MODULE_CODE_CONNECTION_CLOSE) {
        USER_LOG_INFO("MOP channel disconnected.");
        DjiMopChannel_Close(outChannelHandle);
        DjiMopChannel_Destroy(outChannelHandle);
        goto REACCEPT;
    }
}

// Send data
uint8_t sendBuf[64 * 1024];
memset(sendBuf, 0xAB, sizeof(sendBuf));
DjiMopChannel_SendData(outChannelHandle, sendBuf, sizeof(sendBuf), &realLen);
```

#### Close and Destroy

After communication ends, first call `DjiMopChannel_Close()` to close the channel connection, then call `DjiMopChannel_Destroy()` to destroy the channel handle and release resources. After closing the channel, the channel will not be able to send or receive data, but new connections can be re-accepted.

```c
// Close the channel
DjiMopChannel_Close(outChannelHandle);

// Destroy the channel handle
DjiMopChannel_Destroy(outChannelHandle);
```

### MSDK Side

When the Mobile App developed with MSDK uses the SDK interconnection function, it can establish a connection with the specified channel to realize data reception and transmission. **The Mobile App developed based on MSDK can only act as a client, establishing a connection with the specified channel through the channel ID.**



#### Channel Connection

When connecting a channel, specify the channel transmission method and the channel ID to establish a connection with the specified channel, and receive the transmitted data in the way of blocking callback.

* iOS
```c
- (void)connect:(uint16_t)Id pipelineType:(DJITransmissionControlType)transferType withCompletion:(void (^_Nullable)(DJIPipeline *_Nullable pipeline, NSError *_Nullable error))completion;
```

* Android
```java
void connect(int id, @NonNull TransmissionControlType transmissionType, @Nullable CommonCallbacks.CompletionCallback<PipelineError> callback);
```

#### Data Reception

After the channel is connected, use the following interface to receive the data sent by the peer.

* iOS
```c
- (NSData *)readData:(uint32_t)readLength error:(NSError **)error;
```

* Android
```java
int readData(byte[] buff, int length);
```

#### Data Sending

After the channel is connected, use the following interface to send data to the peer.

:::tip Note:
In order to achieve good data transmission effect, it is recommended that the data transmitted each time does not exceed 1KB.
:::

* iOS
```c
- (int32_t)writeData:(NSData *)data error:(NSError **)error;
```

* Android
```java
int writeData(byte[] data);
```

#### Close Channel

After the communication ends, please use the following interface to disconnect the connected channel.

:::tip Note:
* After performing the channel closing operation, the Mobile App developed based on MSDK will clear the local cache information.
* After the channel is closed, DJI SDK will automatically destroy the created channel and release the system resources occupied by the channel.
:::

* iOS
```c
- (void)disconnect:(uint16_t)Id withCompletion:(DJICompletionBlock)completion;
```

* Android
```java
void disconnect(int id, @Nullable CommonCallbacks.CompletionCallback<PipelineError> callback);
```

## Sample Tutorial

This section provides complete implementation examples for two interconnection scenarios to help developers get started quickly.

### Interconnection between MSDK and PSDK

MSDK can only act as a client, and PSDK (gimbal port / E-Port) acts as the server. Both ends need to align the custom channel ID and data protocol.

**PSDK Side (Server)**

The following is the complete process for the PSDK side as a server: Initialize → Create channel → Bind channel ID → Wait for connection → Data send/receive → Close and destroy.

```c
// Step 1: Initialize the MOP channel module
T_DjiReturnCode returnCode = DjiMopChannel_Init();
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("MOP channel init error, stat:0x%08llX.", returnCode);
    return returnCode;
}

// Step 2: Create a channel handle (choose reliable or unreliable transmission)
T_DjiMopChannelHandle channelHandle;
returnCode = DjiMopChannel_Create(&channelHandle, DJI_MOP_CHANNEL_TRANS_RELIABLE);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("MOP channel create error, stat:0x%08llX.", returnCode);
    return returnCode;
}

// Step 3: Bind channel ID
REBIND:
returnCode = DjiMopChannel_Bind(channelHandle, 49152);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("MOP bind channel error: 0x%08llX", returnCode);
    osalHandler->TaskSleepMs(3000);
    goto REBIND;
}

// Step 4: Block and wait for client connection (recommended to call in a separate thread)
T_DjiMopChannelHandle outChannelHandle;
REACCEPT:
returnCode = DjiMopChannel_Accept(channelHandle, &outChannelHandle);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_WARN("MOP accept channel error: 0x%08llX", returnCode);
    osalHandler->TaskSleepMs(3000);
    goto REACCEPT;
}
USER_LOG_INFO("MOP channel connected.");

// Step 5: Data send/receive (use outChannelHandle)
uint8_t recvBuf[100 * 1024];
uint32_t realLen = 0;
returnCode = DjiMopChannel_RecvData(outChannelHandle, recvBuf, sizeof(recvBuf), &realLen);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    if (returnCode == DJI_ERROR_MOP_CHANNEL_MODULE_CODE_CONNECTION_CLOSE) {
        USER_LOG_INFO("MOP channel disconnected.");
        DjiMopChannel_Close(outChannelHandle);
        DjiMopChannel_Destroy(outChannelHandle);
        goto REACCEPT;
    }
}

uint8_t sendBuf[64 * 1024];
memset(sendBuf, 0xAB, sizeof(sendBuf));
DjiMopChannel_SendData(outChannelHandle, sendBuf, sizeof(sendBuf), &realLen);

// Step 6: Close and destroy the channel
DjiMopChannel_Close(outChannelHandle);
DjiMopChannel_Destroy(outChannelHandle);
```

**MSDK Side (Client)**

After the PSDK successfully calls the `DjiMopChannel_Accept` interface, the MSDK can use the `connect` interface to select the specified channel ID and channel type for connection. After the connection is successful, data can be sent and received through `writeData` and `readData`.

* iOS

```objc
// Step 1: Connect to the specified channel of the PSDK server
[pipeline connect:49152
     pipelineType:DJITransmissionControlTypeReliable
   withCompletion:^(DJIPipeline *pipeline, NSError *error) {
    if (error) {
        NSLog(@"Connect failed: %@", error);
        return;
    }
    NSLog(@"Connect success");
}];

// Step 2: Receive data
NSError *error = nil;
NSData *recvData = [pipeline readData:1024 error:&error];
if (error) {
    NSLog(@"Read data error: %@", error);
}

// Step 3: Send data (recommended not to exceed 1KB per transmission)
NSData *sendData = [@"Hello PSDK" dataUsingEncoding:NSUTF8StringEncoding];
int32_t writtenLen = [pipeline writeData:sendData error:&error];
if (error) {
    NSLog(@"Write data error: %@", error);
}

// Step 4: Disconnect the channel
[pipeline disconnect:49152 withCompletion:^(NSError *error) {
    if (error) {
        NSLog(@"Disconnect failed: %@", error);
        return;
    }
    NSLog(@"Disconnected");
}];
```

* Android

```java
// Step 1: Connect to the specified channel of the PSDK server
pipeline.connect(49152, TransmissionControlType.RELIABLE, error -> {
    if (error == null) {
        Log.i(TAG, "Connect success");
    } else {
        Log.e(TAG, "Connect failed: " + error.toString());
    }
});

// Step 2: Receive data
byte[] recvBuf = new byte[1024];
int recvLen = pipeline.readData(recvBuf, recvBuf.length);
Log.i(TAG, "Received " + recvLen + " bytes");

// Step 3: Send data (recommended not to exceed 1KB per transmission)
byte[] sendData = "Hello PSDK".getBytes();
int sentLen = pipeline.writeData(sendData);
Log.i(TAG, "Sent " + sentLen + " bytes");

// Step 4: Disconnect the channel
pipeline.disconnect(49152, error -> {
    if (error == null) {
        Log.i(TAG, "Disconnected");
    }
});
```

### Interconnection between PSDK Gimbal Port and PSDK E-Port

For this scenario, both PSDK (E-Port) and PSDK (gimbal port) can act as client or server. Both ends need to align the custom channel ID and data protocol. The following uses PSDK gimbal port as the server and PSDK E-Port as the client as an example.

**PSDK Gimbal Port (Server)**

The server-side process is the same as the PSDK side in the [Interconnection between MSDK and PSDK](#interconnection-between-msdk-and-psdk) section above.

**PSDK E-Port (Client)**

```c
// Step 1: Initialize the MOP channel module
DjiMopChannel_Init();

// Step 2: Create a channel handle
T_DjiMopChannelHandle channelHandle;
DjiMopChannel_Create(&channelHandle, DJI_MOP_CHANNEL_TRANS_RELIABLE);

// Step 3: Connect to the server (specify channel address and channel ID, blocking, recommended to call in a separate thread)
T_DjiReturnCode returnCode = DjiMopChannel_Connect(channelHandle,
                                                    DJI_CHANNEL_ADDRESS_PAYLOAD_PORT_NO1,
                                                    49152);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("MOP connect error: 0x%08llX", returnCode);
    return returnCode;
}
USER_LOG_INFO("MOP channel connected to server.");

// Step 4: Data send/receive
uint8_t recvBuf[100 * 1024];
uint32_t realLen = 0;
DjiMopChannel_RecvData(channelHandle, recvBuf, sizeof(recvBuf), &realLen);

uint8_t sendBuf[64 * 1024];
memset(sendBuf, 0xAB, sizeof(sendBuf));
DjiMopChannel_SendData(channelHandle, sendBuf, sizeof(sendBuf), &realLen);

// Step 5: Close and destroy the channel
DjiMopChannel_Close(channelHandle);
DjiMopChannel_Destroy(channelHandle);
```
