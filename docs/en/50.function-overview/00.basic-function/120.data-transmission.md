
## Overview
The payload device and the drone use the data transmission module to transparently transmit data between PSDK and MSDK / onboard computer / cloud. PSDK provides three types of data transmission channels:

- **Low-speed data transmission channel**: Strong reliability, dedicated to transmitting signals that require high reliability, such as control instructions and status information.
- **High-speed data transmission channel**: Large bandwidth, mainly used to transmit data with a large amount of data and high real-time requirements, such as radar signals and point cloud data.
- **Cloud data transmission channel**: Sends data to the cloud server through the WebSocket channel of Pilot2.

:::tip Note:
- The PSDK data transmission module transfers data transparently between the payload device, onboard computer, and the aircraft. It allows users to design custom data transmission protocols based on actual application requirements, enabling payload devices developed with PSDK to achieve complex communication with mobile apps or onboard computers.   
- Compatibility note: If the video stream format is set to **DJI H264**, the data stream transmission function will be unavailable. It is recommended to switch to the <a href="./sdk-interconnection.html" target="_blank" rel="noopener noreferrer">SDK Interconnection</a> feature instead.
:::

## Basic Concepts

### Classification of Channels
According to the actual transmission data type and data function, the data transmission channel of PSDK can be divided into command signal transmission channel, high-speed data transmission channel, and cloud data transmission channel, as shown in Figure 1. Signal transmission channel.
* Command signal transmission channel (low-speed): Strong reliability, dedicated to transmitting signals that require high reliability, such as control instructions and status information.
* High-speed data transmission channel: It has a large bandwidth and is mainly used to transmit data with a large amount of data and high real-time requirements, such as radar signals and point cloud data.
* Cloud data transmission channel: Sends payload data to the cloud server through the WebSocket channel of Pilot2, only available on Manifold 3 applications.

### Bandwidth of the Channel
* Channel bandwidth: The amount of data that the data channel can transmit under **theoretical state**
* Real-time bandwidth: The theoretical maximum amount of data that can be transmitted by the data channel in the **working state**
* Actual bandwidth: The amount of data actually transmitted by the data channel

#### Channel Bandwidth Limit
The bandwidth limit of the data transmission channel refers to the **maximum** amount of data (byte/s) that the channel can transmit in unit time.    
Subject to the physical characteristics of the interface components and the actual use environment, the bandwidth of the command signal transmission channel and the high-speed data transmission channel can be divided into **static bandwidth limit** and **dynamic bandwidth limit**.

#### Static Bandwidth Limit  
The static bandwidth limit refers to the **fixed** bandwidth size of the command signal transmission channel, which **cannot be changed** due to the physical properties and inherent electrical properties of the material. #### Dynamic Bandwidth Limit  
Dynamic bandwidth limitation means that the **high-speed data transmission channel** is affected by factors such as link status and electromagnetic environment, and the **maximum** amount of data that the channel can transmit will change dynamically. Therefore, the *actual bandwidth* of the **high-speed data transmission channel** should be lower than the *real-time bandwidth*.
##### Set Bandwidth Usage Ratio
PSDK supports users to set the **high-speed data transmission channel** bandwidth usage ratio for different data types, so as to achieve precise control over the bandwidth occupation of high-speed data transmission channels.
**Actual bandwidth** of a certain type of data = the dynamic bandwidth of the high-speed data transmission channel ✕ Bandwidth allocation ratio.

:::tip Note:
The dynamic bandwidth limit of the command signal transmission channel is equal to the static bandwidth limit.
:::

### Flow Control
The data transmission module of PSDK implements the flow control function by using the flow threshold and buffer to limit the amount of data sent by the payload device to the Mobile App or onboard computer, as shown in Figure 2. Flow control.  

The flow control process of PSDK is as follows:

1. The payload device transmits data information to the onboard computer or Mobile App through the data channel;
2. When the data sent by the payload device is greater than the threshold of the flow control function, the flow control function will temporarily store the data exceeding the **flow threshold** in the buffer;
3. When the buffer is full of data, the data sent by the payload device that **exceeds the flow threshold** will be discarded;
4. When the data channel is idle, the flow control module will send the data temporarily stored in the buffer.

:::tip Note:
* The flow control period of the data transmission module is 1s. In each control period, the amount of data transmitted by the payload device should be less than the **flow threshold** set by the user.
* The flow threshold determines the maximum data that can be transmitted by the current data transmission channel. The threshold is jointly determined by factors such as static bandwidth limit, dynamic bandwidth limit, and the bandwidth occupancy ratio of high-speed data transmission channels.
* The buffer capacity of the command signal transmission channel for flow control is 512 bytes.
:::

### Channel Status
The payload device developed with PSDK can obtain the following information:
  * **Actual bandwidth** of the data transmission channel before the user uses the flow control function (`realtimeBandwidthBeforeFlowController`);
  * **Actual bandwidth** of the data transmission channel after the user uses the flow control function (`realtimeBandwidthAfterFlowController`);
  * The busy state of the channel (`busyState`): When the data of the corresponding channel is stored in the buffer or discarded, the channel state of the data transmission module is "busy".

### Low-Speed Data Transmission

The low-speed data transmission channel (command signal transmission channel) is used to transmit control commands and small data between the payload device and the Mobile App, onboard computer, cloud server, or other payloads, with a maximum of 128 bytes per packet.

#### Initialization

Before using the low-speed data transmission function, you need to initialize the low-speed data transmission channel module.

```c
djiStat = DjiLowSpeedDataChannel_Init();
if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("init data transmission module error.");
    return DJI_ERROR_SYSTEM_MODULE_CODE_UNKNOWN;
}
```

#### Register Data Reception Callback

After constructing and registering the data reception callback function, the payload device developed using PSDK can receive control commands sent from different endpoints through the command signal transmission channel.

**Construct the Callback Function**

Construct the callback function to get and print data sent from the corresponding endpoint.  

```c
static T_DjiReturnCode ReceiveDataFromMobile(const uint8_t *data, uint16_t len)
{
    char *printData = NULL;
    T_DjiOsalHandler *osalHandler = DjiPlatform_GetOsalHandler();

    printData = osalHandler->Malloc(len + 1);
    if (printData == NULL) {
        USER_LOG_ERROR("malloc memory for printData fail.");
        return DJI_ERROR_SYSTEM_MODULE_CODE_MEMORY_ALLOC_FAILED;
    }

    strncpy(printData, (const char *) data, len);
    printData[len] = '\0';
    USER_LOG_INFO("receive data from mobile: %s, len:%d.", printData, len);
    DjiTest_WidgetLogAppend("receive data: %s, len:%d.", printData, len);

    osalHandler->Free(printData);

    return DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS;
}
```

**Register the Callback Function**

Register the callback function by specifying the channel address, so the payload device can receive control commands sent from the corresponding endpoint. The registered channel address differs depending on the mounting position of the payload:

:::tip Note:
This interface supports small-data transparent transmission between payloads.
:::

* **Receive data from Mobile App** (supported by all mounting positions):

```c
channelAddress = DJI_CHANNEL_ADDRESS_MASTER_RC_APP;
djiStat = DjiLowSpeedDataChannel_RegRecvDataCallback(channelAddress, ReceiveDataFromMobile);
if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("register receive data from mobile error.");
    return DJI_ERROR_SYSTEM_MODULE_CODE_UNKNOWN;
}
```

* **Receive data from Cloud Server** (supported by M30/M3D/M4D series models):

```c
channelAddress = DJI_CHANNEL_ADDRESS_CLOUD_API;
djiStat = DjiLowSpeedDataChannel_RegRecvDataCallback(channelAddress, ReceiveDataFromCloud);
if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("register receive data from cloud error.");
    return DJI_ERROR_SYSTEM_MODULE_CODE_UNKNOWN;
}
```

* **Receive data from Onboard Computer** (when payload is mounted on payload port):

```c
channelAddress = DJI_CHANNEL_ADDRESS_EXTENSION_PORT;
djiStat = DjiLowSpeedDataChannel_RegRecvDataCallback(channelAddress, ReceiveDataFromExtensionPort);
if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("register receive data from extension port error.");
    return DJI_ERROR_SYSTEM_MODULE_CODE_UNKNOWN;
}
```

* **Receive data from Payload Device** (when payload is mounted on extension port):

```c
channelAddress = DJI_CHANNEL_ADDRESS_PAYLOAD_PORT_NO1;
djiStat = DjiLowSpeedDataChannel_RegRecvDataCallback(channelAddress, ReceiveDataFromPayload1);
if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("register receive data from payload NO1 error.");
    return DJI_ERROR_SYSTEM_MODULE_CODE_UNKNOWN;
}
```

### High-Speed Data Transmission

The high-speed data transmission channel is used to send large data streams to the Mobile App, with a maximum of 65000 bytes per packet.

:::tip Note:
* The high-speed data transmission channel does not require separate initialization, but you need to call `DjiPlatform_RegHalNetworkHandler` to register the network interface before using it.
* Only payload devices developed based on Linux support using the high-speed data transmission channel.
:::

#### Set Bandwidth Usage Ratio

Users can call the `DjiHighSpeedDataChannel_SetBandwidthProportion` interface to set the bandwidth proportion for data stream, video stream, and download stream in the high-speed data transmission channel. The sum of the three proportions must equal 100.

:::tip Note:
* When the bandwidth usage ratio is not set, the default ratio of video stream, data stream and download stream to high-speed data transmission channel bandwidth is 33%, 33% and 34% respectively.
* The bandwidth proportion takes effect approximately 1s after being set.
:::

```c
const T_DjiDataChannelBandwidthProportionOfHighspeedChannel bandwidthProportionOfHighspeedChannel =
    {10, 60, 30};  // Data stream 10%, Video stream 60%, Download stream 30%

djiStat = DjiHighSpeedDataChannel_SetBandwidthProportion(bandwidthProportionOfHighspeedChannel);
if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Set data channel bandwidth width proportion error.");
    return DJI_ERROR_SYSTEM_MODULE_CODE_UNKNOWN;
}
```

After setup, you can get the remote network address of the data stream for data communication between heterogeneous systems:

```c
char ipAddr[DJI_IP_ADDR_STR_SIZE_MAX];
uint16_t port;

djiStat = DjiHighSpeedDataChannel_GetDataStreamRemoteAddress(ipAddr, &port);
if (djiStat == DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_DEBUG("Get data stream remote address: %s, port: %d", ipAddr, port);
} else {
    USER_LOG_ERROR("get data stream remote address error.");
}
```

### Cloud Data Transmission

The cloud data transmission channel sends payload data to the cloud server through the WebSocket of Pilot2.

:::warning Caution:
* This interface is only available on Manifold 3 applications.
* It is recommended to send more bytes at a time to improve read/write efficiency.
* You need to check the return code and actual sent length to determine whether the transmission was successful.
:::

```c
uint32_t realLen = 0;

djiStat = DjiCloudApi_SendDataByWebSocket(dataToBeSent, sizeof(dataToBeSent), &realLen);
if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("send data to cloud by websocket error.");
} else {
    USER_LOG_INFO("send data to cloud success, real sent length: %d.", realLen);
}
```
