
## Overview

Using the custom widget function of PSDK, developers can encapsulate payload device functions into controls such as buttons, switches, range bars, and selection lists. Through DJI Pilot or Mobile Apps developed based on MSDK, the widget UI is displayed, allowing users to configure parameters and control actions of the payload device without writing mobile app code. Additionally, in multi-payload scenarios, the widget management function supports cross-device subscription and control of other PSDK payload widgets.

The custom widget feature involves two independent sets of APIs:

* **Custom Widget Development Interface** (`dji_widget.h`): Used to register and implement widgets on the current payload device, including UI configuration, widget handlers, floating window messages, and speaker functions.
* **Widget Manager Interface** (`dji_widget_manager.h`): Used to manage widgets of other payload devices at different mounting positions from one PSDK device, including downloading widget files, subscribing to and controlling widget states, and managing speakers.

## Basic Concepts

### Widget Types

Custom widgets support the following 5 widget types:

| Widget Type | Enum Value | Applicable Interface | Description |
|-------------|-----------|---------------------|-------------|
| Button | DJI_WIDGET_TYPE_BUTTON | Main / Config | Press and release states |
| Switch | DJI_WIDGET_TYPE_SWITCH | Main / Config | On/off states |
| Scale (Range Bar) | DJI_WIDGET_TYPE_SCALE | Main / Config | Slider from 0 to 100 |
| List | DJI_WIDGET_TYPE_LIST | Main / Config | Select one from multiple options |
| Integer Input Box | DJI_WIDGET_TYPE_INT_INPUT_BOX | Config | Enter an integer value |

### Widget Configuration File
:::warning Note:
The widget configuration file includes **static configuration file** (`widget_config.json`) and **widget UI icons** (PNG). It is recommended to write the static configuration file first, then design the icons.
:::

The path of the widget configuration file: `sample/sample_c/module_sample/widget/widget_file`
* When the DJI Pilot system language is Chinese, the widget configuration file is `cn_big_screen`
* When the DJI Pilot system language is English, the widget configuration file is `en_big_screen`
* Configuration information in different languages, such as widget number, quantity and type, needs to be consistent.


#### Configuration File Format

`widget_config.json` is a file used to configure the static properties of widgets. When modifying, please strictly follow the syntax rules of [JSON](https://www.json.org/).

:::tip Tips:
* The configuration items in the JSON file are wrapped in a `{}`, and the data is expressed by key-value;
* The Key of JSON must be wrapped in double quotation marks, do not lose the double quotation marks of the Key value;
* JSON values support numbers (including floats and integers), strings, Bool values, arrays (`[]`) and objects (`{}`).
:::

>**Note:** The content after "//" in the following code is a code comment, please do not add this content in the actual JSON configuration file.

#### RTOS Configuration File Conversion

RTOS system does not support file system, please follow the steps below to convert the configuration file to `.h` type file:

* Use the tool `file2c` in the `tools/file2c` directory to generate `.h` header files for **all** custom widget configuration files. For details, please refer to the `Readme.txt` file in the directory;
* `.h` header file is in the `sample/api_sample/widget/widget_file_c` directory;
* Call the interface `DjiWidget_RegDefaultUiConfigByBinaryArray` and `DjiWidget_RegUiConfigByBinaryArray` to load the widget configuration file.
  - Configuration References
    * Chinese configuration files: `file_binary_array_list_cn.h` and `file_binary_array_list_cn.c`
    * English configuration files: `file_binary_array_list_en.h` and `file_binary_array_list_en.c`

### Custom Widget Development

Custom widget development uses the interfaces provided by `dji_widget.h` to display the current PSDK payload device's widget UI on DJI Pilot and respond to user operations.

:::warning Note:
The following code samples are provided as reference examples to help developers understand the calling workflow and implementation approach of each feature. Developers should adapt and adjust based on the actual hardware characteristics and application scenarios of their own payload devices.
:::

In the following flow diagrams, white background indicates interfaces actively called by developers or processing logic within callbacks, and gray background indicates callback functions automatically triggered by the SDK at runtime.

#### UI Configuration

To develop custom widget functionality, you need to first initialize the widget module, obtain the directory of the widget configuration files, and register default configuration and multi-language configuration.

##### Widget Initialization

Before using the "custom widget" function, you need to initialize the widget module of the payload device.

```c
djiStat = DjiWidget_Init();
if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Dji test widget init error, stat = 0x%08llX", djiStat);
    return djiStat;
}
```

##### Set Widget Configuration (Linux)

On Linux systems, register the widget's default UI configuration and multi-language configuration through directory paths to ensure DJI Pilot can correctly display widgets.

:::tip Note:
Configuration items in widget configuration files under different system languages, such as widget number, widget count, and widget type, need to be consistent.
:::

```c
    //Step 2 : Set UI Config (Linux environment)
    char curFileDirPath[WIDGET_DIR_PATH_LEN_MAX];
    char tempPath[WIDGET_DIR_PATH_LEN_MAX];
    djiStat = DjiUserUtil_GetCurrentFileDirPath(__FILE__, WIDGET_DIR_PATH_LEN_MAX, curFileDirPath);
    if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
        USER_LOG_ERROR("Get file current path error, stat = 0x%08llX", djiStat);
        return djiStat;
    }

    if (s_isWidgetFileDirPathConfigured == true) {
        snprintf(tempPath, WIDGET_DIR_PATH_LEN_MAX, "%swidget_file/en_big_screen", s_widgetFileDirPath);
    } else {
        snprintf(tempPath, WIDGET_DIR_PATH_LEN_MAX, "%swidget_file/en_big_screen", curFileDirPath);
    }

    //set default ui config path
    djiStat = DjiWidget_RegDefaultUiConfigByDirPath(tempPath);
    if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
        USER_LOG_ERROR("Add default widget ui config error, stat = 0x%08llX", djiStat);
        return djiStat;
    }

    //set ui config for English language
    djiStat = DjiWidget_RegUiConfigByDirPath(DJI_MOBILE_APP_LANGUAGE_ENGLISH,
                                             DJI_MOBILE_APP_SCREEN_TYPE_BIG_SCREEN,
                                             tempPath);
    if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
        USER_LOG_ERROR("Add widget ui config error, stat = 0x%08llX", djiStat);
        return djiStat;
    }

    //set ui config for Chinese language
    if (s_isWidgetFileDirPathConfigured == true) {
        snprintf(tempPath, WIDGET_DIR_PATH_LEN_MAX, "%swidget_file/cn_big_screen", s_widgetFileDirPath);
    } else {
        snprintf(tempPath, WIDGET_DIR_PATH_LEN_MAX, "%swidget_file/cn_big_screen", curFileDirPath);
    }

    djiStat = DjiWidget_RegUiConfigByDirPath(DJI_MOBILE_APP_LANGUAGE_CHINESE,
                                             DJI_MOBILE_APP_SCREEN_TYPE_BIG_SCREEN,
                                             tempPath);
    if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
        USER_LOG_ERROR("Add widget ui config error, stat = 0x%08llX", djiStat);
        return djiStat;
    }
```

#### Widget Handler

Register the widget handler function list through the `DjiWidget_RegHandlerList` interface to bind payload device functions to specified widgets. When users operate widgets on DJI Pilot, the SDK will automatically call the `SetWidgetValue` callback; the SDK will also periodically call the `GetWidgetValue` callback to synchronize widget states.

```c
    djiStat = DjiWidget_RegHandlerList(s_widgetHandlerList, s_widgetHandlerListCount);
    if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
        USER_LOG_ERROR("Set widget handler list error, stat = 0x%08llX", djiStat);
        return djiStat;
    }
```

#### Floating Window Message

After initialization is complete, you can use the `DjiWidgetFloatingWindow_ShowMessage` interface to display payload device status information in real time in the floating window on the DJI Pilot main interface. The sample code periodically updates the floating window content through a background task.

```c
djiStat = DjiWidgetFloatingWindow_ShowMessage(message);
if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Floating window show message error, stat = 0x%08llX", djiStat);
}
```

#### Speaker Function

After registering the speaker handler through `DjiWidget_RegSpeakerHandler`, the payload device can implement TTS playback, voice playback, volume adjustment, and other functions. The speaker handler contains 8 callback function pointers, covering operations such as getting speaker state, setting work mode/playback mode/volume, starting/stopping playback, and data transmission.

:::tip Note:
For detailed introduction to the speaker function, widget UI description, and complete implementation code, please refer to <a href="./speaker.html" target="_blank" rel="noopener noreferrer">Speaker Function</a>.
:::

```c
s_speakerHandler.GetSpeakerState = GetSpeakerState;
s_speakerHandler.SetWorkMode = SetWorkMode;
s_speakerHandler.StartPlay = StartPlay;
s_speakerHandler.StopPlay = StopPlay;
s_speakerHandler.SetPlayMode = SetPlayMode;
s_speakerHandler.SetVolume = SetVolume;
s_speakerHandler.ReceiveTtsData = ReceiveTtsData;
s_speakerHandler.ReceiveVoiceData = ReceiveAudioData;

djiStat = DjiWidget_RegSpeakerHandler(&s_speakerHandler);
if (djiStat != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Register speaker handler error: 0x%08llX", djiStat);
    return djiStat;
}
```

#### Widget File Download

##### Initialize Widget Manager Module

```c
DjiWidgetManager_Init();
```

##### Download Widget Files

Call `DjiWidgetManager_WidgetDownloadFileList` to get the widget file list, register the download callback, and download the required files by index.

```c
// Get widget file list
DjiWidgetManager_WidgetDownloadFileList(position, &fileList);

// Register download data callback
DjiWidgetManager_RegDownloadFileDataCallback(position, DjiWidgetManager_UsrDownloadCallback);

// Download widget file by index
DjiWidgetManager_DownloadFileByIndex(position, fileIndex);
```

#### Widget State Subscription and Control

Subscribe to the widget states of a PSDK device mounted at a specified position. When the state changes, the callback function will be notified. You can also actively set widget states via `SetWidgetState` to control the target device.

```c
// Subscribe to widget states
DjiWidgetManager_SubscribePayloadWidgetStates(position, DjiTestWidgetManager_RecvWidgetStatesCallback);

// Set widget state
DjiWidgetManager_SetWidgetState(position, state);

// Unsubscribe
DjiWidgetManager_UnsubscribePayloadWidgetStates(position);
```

##### Example: Control Zenmuse S1 Spotlight

Payload devices that support widgets can be controlled through the widget management function. The following example uses the Zenmuse S1 drone spotlight:

**1. Obtain the widget file list**

Call the `DjiWidgetManager_WidgetDownloadFileList` API to download the list of widget files supported by the payload device, obtaining the widget description files (JSON) and corresponding icon resource information.

**2. Download the widget description file**

Based on the file list information, use the `DjiWidgetManager_DownloadFileByIndex` API to download the required widget files. After the download is complete, the widget description file `widget_config.json` can be obtained. This file describes the widget information of the spotlight, including: widget type, widget name, widget icon configuration, etc.

**3. Control the Spotlight by Setting Widget States**

Based on the widget descriptions defined in `widget_config.json`, the operating state of the spotlight can be changed by setting widget states. For example, the following code turns on the Zenmuse S1 spotlight mounted on E-Port V2 port 1:

```c
   T_DjiWidgetStates state;
   state.widget_index = 3;
   state.widget_value = 1;
   state.widget_type = DJI_WIDGET_TYPE_SWITCH;

   DjiWidgetManager_SetWidgetState(1, &state);
```

By using this approach, payload devices can retrieve widget information from other payloads and set widget states accordingly, achieving the same control capabilities as operating widget icons in DJI Pilot. This mechanism can be used to enable payload linkage control, cross-payload operations, or automated application scenarios.

#### Speaker Management

On the Matrice 400 aircraft, DJI PSDK provides an interface to control the DJI V1 speaker by setting widget values.

```c
// Subscribe to speaker widget states
DjiWidgetManager_SubscribeSpeakerStates(position, DjiTestWidgetManager_RecvSpeakerStatesCallback);

// Send audio files
DjiWidgetManager_SendSpeakerAudioData(position, &audioFileInfo);

// Set speaker parameters (volume, playback mode, playback content)
DjiWidgetManager_SetSpeakertState(position, &param);

// Unsubscribe from speaker widget states
DjiWidgetManager_UnsubscribeSpeakerStates(position);
```

### How to use custom widgets in waypoint missions?

DJI's drones support users adding custom widget operations to waypoint missions when using payload devices with custom widget functionality, so that the drone can automatically control the payload device's widgets at specified waypoints during waypoint mission execution.

The custom widget function supports adding the following widgets to waypoint missions:
* Button
* Switch
* Range Bar

The steps to add widgets when the drone is executing a waypoint mission are as follows:
1. Enter the DJI Pilot flight route page
2. Add waypoints on the map
3. When adding a waypoint, add a custom widget action, such as turning the switch on and off, as shown in Figure 6.
4. Save the route
