## Overview

Local upgrade is a feature for upgrading payload device firmware. Developers implement the firmware transfer, firmware verification, and firmware replacement workflow through the upgrade interfaces provided by PSDK. Once integrated, users can select a local firmware file in DJI Assistant 2 to upgrade the payload device firmware.

Through the local upgrade module, developers can:

* **Configure upgrade parameters**: Specify the current firmware version number and firmware transfer protocol (FTP or DCFTP)
* **Receive upgrade firmware**: Receive new firmware files from DJI Assistant 2 via FTP or DCFTP protocol
* **Control upgrade workflow**: Respond to upgrade stage events through callback functions (enter upgrade mode, check firmware, start upgrade, finish upgrade)
* **Push upgrade status**: Report upgrade progress, device reboot information, and upgrade results to the terminal APP in real time
## API Overview

Developers need to call the initialization interface to complete the upgrade module configuration and register upgrade workflow callback functions through `DjiUpgrade_RegHandler()`. Firmware transfer supports two protocols: FTP and DCFTP. When using DCFTP, additional file transfer callbacks must be implemented.

## Basic Concepts

### Firmware Transfer Protocol

Developers need to specify the firmware transfer protocol when calling `DjiUpgrade_Init()`. PSDK supports two transfer methods:

- **FTP Protocol**: Transfers firmware via Ethernet using the standard FTP protocol, offering fast transfer speeds. An FTP server must be deployed for the payload device. For details, see <a href="local-update.html#deploying-ftp-server-optional">Deploying FTP Server</a>.

:::tip Note:
Only payload devices developed on the Linux platform support transferring firmware via Ethernet using the FTP protocol.
:::

- **DCFTP Protocol** (DJI Common File Transfer Protocol): A proprietary file transfer protocol by DJI that transfers firmware through the command signal transmission channel. Developers need to implement the three callback functions in `T_DjiUpgradeDcftpFileTransferOpt` (`start`, `transfer`, `finish`) and bind them when calling `DjiUpgrade_Init()`.

:::tip Note:
* Payload devices using RTOS or without an Ethernet port can use the DCFTP protocol to transfer firmware.
* Since this method uses the command signal transmission channel, the transfer speed is slower.
:::

### Upgrade Stages

The upgrade process progresses through stages. Developers push the corresponding state information at different stages through `DjiUpgrade_PushUpgradeState()`:

| Upgrade Stage | Enum Value | Description | Push Content |
|---------|--------|------|---------|
| Idle | DJI_UPGRADE_STAGE_IDLE | Not in upgrade mode, running normally | — |
| Ongoing | DJI_UPGRADE_STAGE_ONGOING | Upgrade operation in progress | Upgrade progress (0~100%) |
| Device Reboot | DJI_UPGRADE_STAGE_DEVICE_REBOOT | Upgrade complete, waiting for reboot | Reboot timeout (seconds) |
| Upgrade End | DJI_UPGRADE_STAGE_END | Reports upgrade result after reboot | Upgrade result (success/failure) |

### Upgrade End States

| End State | Enum Value | Description |
|---------|--------|------|
| Upgrade Success | DJI_UPGRADE_END_STATE_SUCCESS | Firmware upgrade succeeded |
| Unknown Error | DJI_UPGRADE_END_STATE_UNKNOWN_ERROR | An unknown error occurred during the upgrade |

### Firmware Naming Rules

The naming format for upgrade firmware files is `Product Name_Vaa.bb.cc.dd.bin`:

- **Product Name**: The payload product name (if the developer has set a payload alias, this name will be the alias)
- **Vaa.bb.cc.dd**: Four-digit version number for the payload

:::tip Note:
The version number in the firmware file name must be consistent with the version number defined in the code, otherwise the payload device may fail to upgrade.
:::

### Upgrade Principle

#### Linux Program File Upgrade Principle
Using the upgrade feature, you can obtain the firmware file that needs to be updated (via FTP or DCFTP protocol), replace the original running program file with the firmware file, and complete the firmware upgrade after the system restarts.
> Related References
> * Payload device upgrade process: `module_sample/upgrade/` 
> * Using local upgrade feature: `platform/linux/manifold2/application/main.c`
> * Upgrading firmware for payload devices developed on Linux platforms: `platform/linux/common/upgrade_platform_opt`

#### STM32F4 Microcontroller Program Upgrade Principle
Payload devices developed with STM32F4 directly read the firmware file from Flash and run the payload device program. Therefore, developers need to flash the Bootloader first and then the application firmware. For steps on flashing the Bootloader, please refer to <a href="../../faq.html#how-to-flash-the-bootloader-on-the-stm32f4-discovery-board" target="_blank" rel="noopener noreferrer">FAQ</a>.   

1. After the STM32F4 platform is powered on, it will start the MCU
2. Run the Bootloader and check the upgrade status:
   * If no firmware upgrade is needed, the Bootloader will jump to the application firmware area and run the application firmware
   * If the payload device firmware needs to be upgraded, the Bootloader will replace the firmware file, then jump to the application firmware area and run the application firmware

> **Related References**
> * Implementing Bootloader: `platform/rtos_freertos/stm32f4_discovery/bootloader`
> * Bootloader project directory: `platform/rtos_freertos/stm32f4_discovery/project/mdk_bootloader`
> * Implementing upgrade feature: `api_sample/upgrade/`
> * STM32F4 upgrade: `platform/rtos_freertos/stm32f4_discovery/drivers/upgrade_platform_opt_stm32`
> * Initializing upgrade feature: `platform/rtos_freertos/stm32f4_discovery/application/application.c`

:::tip Note:
 `stm32f4_discovery` in the above directories can be either `psdk_development_board_1.0` or `stm32f4_eval`.
:::

#### Modify Flash Address Space (Optional)
1. Modify address definitions:
Modify the address definitions in the `platform/rtos_freertos/STM32F4Platform/drivers/BSP/flash_if.h` file
```c
/* End of the Flash address */
#define FLASH_END_ADDRESS                   0x080FFFFF

/* Define the address from where user application will be loaded.
   NOTE the 1st sector 0x08000000-0x08007FFF is reserved for the IAP code */
#define APPLICATION_ADDRESS                 ADDR_FLASH_SECTOR_4
#define APPLICATION_ADDRESS_END             (ADDR_FLASH_SECTOR_8 - 1)

/* Define the user application size */
#define APPLICATION_FLASH_SIZE             (APPLICATION_ADDRESS_END - APPLICATION_ADDRESS + 1)

/* Define the address from where user application will be stored in upgrade mode */
#define APPLICATION_STORE_ADDRESS           ADDR_FLASH_SECTOR_8
#define APPLICATION_STORE_ADDRESS_END       (FLASH_END_ADDRESS)

/* Define the address for param store */
#define APPLICATION_PARAM_STORE_ADDRESS     ADDR_FLASH_SECTOR_2
#define APPLICATION_PARAM_STORE_ADDRESS_END (ADDR_FLASH_SECTOR_4 - 1)
```

Address allocation:
* bootloader: 0x08000000～0x08007FFF
* Parameter Store Area: 0x08008000～0x0800FFFF
* Application Firmware: 0x08010000～0x0807FFFF
* Upgrade Firmware Store Area: 0x08080000～0x080FFFFF


2. Configure interrupt vector
In the `platform/rtos_freertos/STM32F4Platform/drivers/CMSIS/Device/Source/system_stm32f4xx.c` file, fill in the offset address of the application firmware

```c
/*!< Uncomment the following line if you need to relocate your vector Table in
     Internal SRAM. */

//attention : this value is equal ( application address - 0x08000000 )
#define VECT_TAB_OFFSET  0x10000
#else
#define VECT_TAB_OFFSET  0x00
#endif
```

3. Modify project configuration information
Modify the project configuration information in the Bootloader and application firmware, and fill in the correct Flash address.
* Bootloader project directory: `platform/rtos_freertos/stm32f4_discovery/project/mdk_bootloader`
* Application firmware project directory: `platform/rtos_freertos/stm32f4_discovery/project/mdk`

### Initialization

Before using the local upgrade feature, you need to construct the upgrade configuration (including the current firmware version number and transfer protocol information), then initialize the upgrade module and register the upgrade workflow callbacks.

**Construct upgrade configuration:**

```c
T_DjiUpgradeConfig upgradeConfig = {
    .currentFirmwareVersion = {1, 0, 0, 0},
    .firmwareTransferInfo = {
        .transferType = DJI_FIRMWARE_TRANSFER_TYPE_DCFTP,
        // FTP mode requires specifying port: .ftpTransferInfo.port = 21,
        // DCFTP mode requires binding transfer callbacks:
        .dcftpFileTransferOpt = {
            .start = DjiTestCommonFileTransfer_Start,
            .transfer = DjiTestCommonFileTransfer_Transfer,
            .finish = DjiTestCommonFileTransfer_Finish,
        },
    },
};
```

**Initialize upgrade module:**

```c
returnCode = DjiUpgrade_Init(&upgradeConfig);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("DjiUpgrade_Init error, return code = %d", returnCode);
    return returnCode;
}
```

**Register upgrade workflow callbacks:**

Developers need to implement the four callback functions in `T_DjiUpgradeHandler` and register them with the SDK through `DjiUpgrade_RegHandler()`:

```c
T_DjiUpgradeHandler s_upgradeHandler = {
    .EnterUpgradeMode = DjiTest_EnterUpgradeMode,
    .CheckFirmware = DjiTest_CheckFirmware,
    .StartUpgrade = DjiTest_StartUpgrade,
    .FinishUpgrade = DjiTest_FinishUpgrade,
};

returnCode = DjiUpgrade_RegHandler(&s_upgradeHandler);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("DjiUpgrade_RegHandler error, return code = %d", returnCode);
    return returnCode;
}
```

**Enable local upgrade:**

```c
returnCode = DjiUpgrade_EnableLocalUpgrade();
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("DjiUpgrade_EnableLocalUpgrade error, return code = %d", returnCode);
    return returnCode;
}
```

### Upgrade Workflow Callbacks

After DJI Assistant 2 triggers the upgrade, the SDK will call the registered callback functions in sequence. The following are typical implementations for each callback:

#### Enter Upgrade Mode

The SDK calls `EnterUpgradeMode` before starting firmware transfer. Developers can perform pre-upgrade preparation work in this callback (such as clearing the firmware storage area) and inform the SDK of the required wait time through `waitTime`.

```c
static T_DjiReturnCode DjiTest_EnterUpgradeMode(uint16_t *waitTime)
{
    *waitTime = DJI_TEST_ENTER_UPGRADE_WAIT_TIME;  // Wait 10 seconds
    s_isNeedEnterUpgradeModeProcess = true;         // Trigger background task to clear storage area

    return DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS;
}
```

#### Check Firmware

After firmware transfer is complete, the SDK calls the `CheckFirmware` callback. Developers can perform firmware signature verification, decryption, and other operations here.

```c
static T_DjiReturnCode DjiTest_CheckFirmware(void)
{
    // Add firmware signature verification and decryption logic here
    return DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS;
}
```

#### Start Upgrade

After firmware verification passes, the SDK calls the `StartUpgrade` callback. Developers need to switch the upgrade stage to `DJI_UPGRADE_STAGE_ONGOING` and begin pushing upgrade progress.

```c
static T_DjiReturnCode DjiTest_StartUpgrade(void)
{
    T_DjiOsalHandler *osalHandler = DjiPlatform_GetOsalHandler();

    osalHandler->MutexLock(s_upgradeStateMutex);
    s_upgradeState.upgradeStage = DJI_UPGRADE_STAGE_ONGOING;
    s_upgradeState.upgradeOngoingInfo.upgradeProgress = 0;
    osalHandler->MutexUnlock(s_upgradeStateMutex);

    return DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS;
}
```

#### Finish Upgrade

After the device reboots and pushes the upgrade result, the SDK calls the `FinishUpgrade` callback. Developers need to switch the upgrade stage back to `DJI_UPGRADE_STAGE_IDLE`.

```c
static T_DjiReturnCode DjiTest_FinishUpgrade(void)
{
    T_DjiOsalHandler *osalHandler = DjiPlatform_GetOsalHandler();

    osalHandler->MutexLock(s_upgradeStateMutex);
    s_upgradeState.upgradeStage = DJI_UPGRADE_STAGE_IDLE;
    osalHandler->MutexUnlock(s_upgradeStateMutex);

    return DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS;
}
```

### State Push

During the upgrade process, developers need to continuously push the upgrade state through `DjiUpgrade_PushUpgradeState()`. The push workflow is as follows:

1. After `StartUpgrade` is called, set the stage to `DJI_UPGRADE_STAGE_ONGOING` and push `upgradeOngoingInfo` when the upgrade progress changes
2. After the upgrade operation completes, switch the stage to `DJI_UPGRADE_STAGE_DEVICE_REBOOT`, push the reboot timeout information, then reboot the device
3. After the device reboots, switch the stage to `DJI_UPGRADE_STAGE_END` and continuously push the upgrade result (recommended at 1 Hz frequency) until `FinishUpgrade` is called

```c
// ONGOING stage: Push upgrade progress
s_upgradeState.upgradeStage = DJI_UPGRADE_STAGE_ONGOING;
s_upgradeState.upgradeOngoingInfo.upgradeProgress = progress;  // 0~100
DjiUpgrade_PushUpgradeState(&s_upgradeState);

// DEVICE_REBOOT stage: Push reboot timeout
s_upgradeState.upgradeStage = DJI_UPGRADE_STAGE_DEVICE_REBOOT;
s_upgradeState.upgradeRebootInfo.rebootTimeout = 30;  // 30 seconds
DjiUpgrade_PushUpgradeState(&s_upgradeState);

// END stage: Push upgrade result (after device reboot)
s_upgradeState.upgradeStage = DJI_UPGRADE_STAGE_END;
s_upgradeState.upgradeEndInfo.upgradeEndState = DJI_UPGRADE_END_STATE_SUCCESS;
DjiUpgrade_PushUpgradeState(&s_upgradeState);
```

### DCFTP File Transfer (Optional)

When using the DCFTP protocol to transfer firmware, developers need to implement the three callback functions in `T_DjiUpgradeDcftpFileTransferOpt`. The SDK will automatically call these callbacks during the firmware transfer phase.

#### Start Transfer

```c
T_DjiReturnCode DjiTestCommonFileTransfer_Start(const T_DjiUpgradeFileInfo *fileInfo)
{
    // Clear transfer state
    memset(&s_fileInfo, 0, sizeof(s_fileInfo));
    s_alreadyTransferFileSize = 0;

    // Create local file for writing
    returnCode = DjiTest_CreateUpgradeProgramFile(fileInfo);
    if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
        return returnCode;
    }

    // Save file information
    memcpy(&s_fileInfo, fileInfo, sizeof(T_DjiUpgradeFileInfo));
    return DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS;
}
```

#### Receive Data

```c
T_DjiReturnCode DjiTestCommonFileTransfer_Transfer(const uint8_t *data, uint16_t dataLen)
{
    // Write firmware data
    returnCode = DjiTest_WriteUpgradeProgramFile(s_alreadyTransferFileSize, data, dataLen);
    if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
        return returnCode;
    }

    s_alreadyTransferFileSize += dataLen;
    return DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS;
}
```

#### Finish Transfer

```c
T_DjiReturnCode DjiTestCommonFileTransfer_Finish(const uint8_t md5[DJI_MD5_BUFFER_LEN])
{
    uint8_t localMd5[DJI_MD5_BUFFER_LEN] = {0};

    // Verify file size
    if (s_alreadyTransferFileSize != s_fileInfo.fileSize) {
        return DJI_ERROR_SYSTEM_MODULE_CODE_SYSTEM_ERROR;
    }

    // Calculate and verify MD5
    DjiTestFile_GetUpgradeFileMd5(localMd5);
    if (memcmp(localMd5, md5, DJI_MD5_BUFFER_LEN) != 0) {
        return DJI_ERROR_SYSTEM_MODULE_CODE_SYSTEM_ERROR;
    }

    // Close file
    DjiTest_CloseUpgradeProgramFile();
    return DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS;
}
```

## Sample Tutorial

### Configure Runtime Environment

Please refer to <a href="../../payload-quick-start/quick-demo/raspberry-pi.html#running-demo" target="_blank" rel="noopener noreferrer">Quick Demo</a> to compile the program that supports the local upgrade feature.

#### Linux Platform
To use the upgrade feature, the program needs to be set to start by default. Please follow these steps:
1. Copy the compiled application to the `/usr/local/bin/` directory;
2. Add the following configuration items in `/etc/rc.local`:
   * `chmod 666 /dev/ttyUSB0`
   * `chmod 755 /usr/local/bin/dji_sdk_demo_linux`
   * `/usr/local/bin/dji_sdk_demo_linux&`
   :::tip Note:
   ttyUSB0 is the serial port device connected to the payload device. Developers can modify this name according to their actual setup.
   :::
3. Restart the payload device and check whether the program is running normally using the terminal command `ps aux | grep dji_sdk_demo_linux`.

#### Deploying FTP Server (Optional)

:::tip Note:
Deploying an FTP server is only required when using the FTP protocol to transfer firmware. If using the DCFTP protocol, you can skip this step.
:::

Follow the steps below to deploy an FTP server using vsftpd:

**1. Install FTP Server**

1. Download [vsftpd]( https://terra-1-g.djicdn.com/fee90c2e03e04e8da67ea6f56365fc76/SDK%20%E6%96%87%E6%A1%A3/PSDK/vsftpd-3.0.3.tar.gz).
2. Install the vsftpd server package:
:::tip Note:
For the complete installation method, please refer to the INSTALL file in the directory to install vsftpd.
:::

   * Use `tar -zxvf vsftpd-*.*.*.tar.gz` command to extract the installation package
   * Enter the `cd vsftpd-*.*.*/` directory
   * Install the FTP server in the following order:
   ```c
    make
    su
    cp vsftpd /usr/local/sbin/vsftpd
    cp vsftpd.conf.5 /usr/local/man/man5
    cp vsftpd.8 /usr/local/man/man8
    cp vsftpd.conf /etc
   ```
3. Create the secure_chroot_dir directory: `mkdir /usr/share/empty`

**2. Configure FTP Server**

1. Modify the configuration items:
   * In the `/etc/vsftpd.conf` file, change anonymous_enable to NO
    ```c
     anonymous_enable=NO
    ```
   * Set the following configuration items:
    ```c
    local_enable=YES
    write_enable=YES
    ```

2. Add users
* Use the `adduser` command to specify the user directory with `--home`
* Use the `userdel -r` command to delete users
* Add user permissions for upgrading payload device firmware: `adduser psdk_payload_ftp --home /upgrade`
* Enter the password when prompted: DJi_#$31

**3. Run FTP Server**

1. Run the FTP server using the `sudo /usr/local/sbin/vsftpd &` command
2. Configure startup items: add `/usr/local/sbin/vsftpd &` to `/etc/rc.local`
3. Use the command `ps aux | grep vsftpd` to check the running status of the FTP service

#### STM32F4 Platform
To use the local upgrade feature on the STM32F4 platform, developers need to first <a href="../../faq.html#how-to-flash-the-bootloader-on-the-stm32f4-discovery-board" target="_blank" rel="noopener noreferrer">flash the Bootloader into the development platform</a>, then flash the payload device firmware. The `STM32F4Platform` in the following directory can be `psdk_development_board_1.0` (using the payload device development board) or `stm32f4_eval` (using the STM32 development board).

1. Flash the Bootloader into the microcontroller. The Bootloader project directory is:
 * samples/sample_c/platform/rtos_freertos/stm32f4_discovery/project/mdk_bootloader 
2. Flash the application firmware into the microcontroller. The application firmware directory is:
 * samples/sample_c/platform/rtos_freertos/stm32f4_discovery/project/mdk

:::tip Note:
* Bootloader is a program that runs when the MCU is powered on, used to update and execute the application firmware.
* Application firmware: implements the software functionality of the payload device, compiling the Payload SDK Lib.
:::

### Compile Upgrade Firmware
1. Modify the firmware version number      
Modify the version number of the firmware in the `T_DjiTestUpgradeConfig` structure definition.
:::tip Note:
 When modifying the version number, the version number must not be lower than the current version. For example, if the current firmware version of the payload device is V02.01.00.03, please change the version number to V02.01.00.04, as shown in the following example.
:::

```c
    T_DjiTestUpgradeConfig testUpgradeConfig = {
        .firmwareVersion = {1, 0, 0, 0},
        .transferType = DJI_FIRMWARE_TRANSFER_TYPE_DCFTP,
        .needReplaceProgramBeforeReboot = true
    };
```
2. Compile the file
Compile the firmware file required for the payload device upgrade:
* STM32: The payload device firmware is the `dji_sdk_demo_linux.bin` file in the STM32F4 project directory
* Linux: The payload device firmware is the compiled `dji_sdk_demo_linux` program file

3. Modify the firmware file name    
After recompiling the firmware file, rename the compiled firmware according to the [firmware naming rules](#firmware-naming-rules), such as `PSDK_APPALIAS_V02.01.00.04.bin`.

### Execute Firmware Upgrade
Open DJI Assistant 2 and select the compiled firmware upgrade file (PSDK_APPALIAS_V02.01.00.04.bin) to upgrade the firmware.
