## Overview

To ensure that drones meet fundamental safety requirements, the European Union has issued the UAV Regulation EU 2019/945 for UAS certification. Drones classified under categories C5 and C6, as special permitted category drones, must undergo different compliance tests to verify their functionality. The drone systems must pass a series of compliance tests conducted by certified laboratories before they can enter the European market.

To comply with the EU C6 compliance certification, PSDK provides the GEO Caging feature, where the drone exhibits different flight behaviors within three distinct zones.
GEO Caging includes an operational area and a contingency area. The aircraft should operate within the operational area. If the aircraft enters the contingency area, it will hover with continuous alerts, and the pilot must manually fly it back to the operational area. If the aircraft flies beyond the contingency area, the Flight Termination System (FTS) will be triggered. If the aircraft is equipped with a parachute, it will deploy the parachute for an emergency landing. Please verify the operational target points before the mission or pay attention to aircraft alerts during flight.

## Basic Concepts

### Terminology

**Flight Geography Area (FG)**

In this area, the aircraft can perform normal takeoff, landing, and flight operations.

**Contingency Area (CA)**

In this area, the aircraft cannot take off or land, and intelligent features such as return-to-home and waypoint navigation are unavailable. If the aircraft reaches the edge of the contingency area, it will brake and hover.

**Operation Volume (OV)**

The operation volume includes the Flight Geography Area (FG) and the Contingency Area (CA). If the aircraft flies beyond the operation volume, the Flight Termination System (FTS) will be triggered, and the parachute will be deployed for landing.

**Flight Termination System (FTS)**

A set of equipment and software independent of the aircraft's own control system that proactively and forcibly stops flight when safety hazards are detected.

The following code is provided as reference examples to help developers understand the calling process and implementation approach for each feature. Developers can adapt and adjust according to their own payload device hardware characteristics and application scenarios.

### Using the FTS Feature

Developers need to provide an FTS signal callback function that implements the FTS signal trigger within the callback and returns the correct execution result. If the return value is incorrect, the FTS callback will be continuously triggered to ensure notification is delivered.

:::warning Warning:
- Since the FTS trigger is a one-time action per flight cycle, only a registration interface for the callback function is provided, without a deregistration interface.
- FTS feature usage varies by aircraft model.
  - For the Matrice 400, the payload device must output a PWM waveform with a frequency of 400 Hz and a duty cycle of 50% to the FTS pin on the 4th E-Port V2 interface.
  - For the Matrice 3D, please follow the subsequent instructions to use the FTS feature.
:::

The following diagram illustrates the complete FTS software callback flow: the developer first initializes the flight control module and registers the callback function. When the flight controller triggers an FTS event, the SDK will invoke the registered callback. If the callback returns a failure, the flight controller will continuously re-trigger until success.

#### Initialize the Flight Control Module

Before using any flight control-related APIs, you need to call the DjiTest_FlightControlInit interface to initialize the flight control module.

```c
returnCode = DjiTest_FlightControlInit(ridInfo);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Init flight Control sample failed,error code:0x%08llX", returnCode);
    return returnCode;
}
```

#### Implement the FTS Callback Function

In a real environment, developers need to implement the FTS signal trigger action within the callback (such as outputting a PWM propeller-stop signal) and return the execution result. If the return indicates failure, the flight controller will re-trigger the callback. The following example code simulates a scenario where the first trigger fails and the flight controller retries successfully, for developer reference:

```c
static uint32_t s_ftsTriggerCount = 0;

T_DjiReturnCode DjiTest_TriggerFtsEventCallback(void)
{
    USER_LOG_INFO("Received FTS Trigger event, count = %d.", s_ftsTriggerCount);

    if (s_ftsTriggerCount == 0) {
        /* Simulate a first trigger failure scenario: return an error value, flight controller will call this callback again */
        USER_LOG_WARN("Note: Simulate a trigger failure scenario and return an error value, "
                      "this function will be invoked again.");
        s_ftsTriggerCount++;
        return DJI_ERROR_SYSTEM_MODULE_CODE_SYSTEM_ERROR;
    } else {
        /* In actual development, trigger the FTS propeller-stop action via PWM signal here */
        USER_LOG_WARN("Note: This is an empty implementation, and the FTS signal "
                      "needs to be triggered by the PWM signal.");
        return DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS;
    }
}
```

#### Register the Callback Function

```c
returnCode = DjiFlightController_RegTriggerFtsEventCallback(DjiTest_TriggerFtsEventCallback);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Register trigger FTS event callback failed.");
    return returnCode;
} else {
    s_isFtsCallbackRegistered = true;
    USER_LOG_INFO("Register trigger FTS event callback successfully."
                    "Please wait for the aircraft to trigger the payload to execute FTS action.");
}
```

### Using the EFTS Feature

EFTS outputs a hardware PWM signal with specific specifications from the payload interface to the flight platform. When the signal meets the required voltage, frequency, and duty cycle conditions, the flight platform will immediately execute a **motor propeller-stop/shutdown** operation without relying on any software command chain.

:::warning Warning:
Matrice 4D/Matrice 4TD, Matrice 4E/Matrice 4T, and Matrice 400 all support the EFTS feature.  
Among them, Matrice 4D/Matrice 4TD supports the E-Port Lite interface; Matrice 4E/Matrice 4T supports both E-Port and E-Port Lite interfaces; Matrice 400 supports only Port No. 4.  
The hardware signal requirements for the payload FTS interface are as follows: voltage 3.3 V, duty cycle 50%, pulse frequency 200 Hz.
:::

The following diagram illustrates the complete EFTS hardware trigger flow: the developer first enables the FTS PWM trigger port on the ground, then during flight the payload outputs a PWM signal that meets the specifications to trigger propeller-stop on the flight platform, and finally confirms the propeller-stop result by subscribing to ESC data.

#### Enable the EFTS Trigger Source

Enable the EFTS trigger source on the ground to select/enable the FTS (motor stop) PWM trigger port on the flight controller side.

```c
T_DjiReturnCode DjiFts_SelectFtsPwmTrigger(E_DjiMountPosition position);
```

#### Trigger Propeller-Stop

The payload triggers propeller-stop by outputting a compliant FTS hardware PWM signal. After triggering, you can subscribe to `DJI_FC_SUBSCRIPTION_TOPIC_ESC_DATA` to get the speed and status of each ESC to confirm whether the propeller-stop has taken effect. When all ESCs report a `speed` of 0, the propeller-stop was successful.

```c
T_DjiFcSubscriptionEscData escData;

/* Subscribe to ESC data to confirm propeller-stop result */
returnCode = DjiFcSubscription_GetLatestValueOfTopic(
    DJI_FC_SUBSCRIPTION_TOPIC_ESC_DATA,
    (uint8_t *)&escData,
    sizeof(T_DjiFcSubscriptionEscData),
    NULL);

if (returnCode == DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    for (int i = 0; i < 8; i++) {
        USER_LOG_INFO("ESC[%d]: speed=%d rpm, current=%d mA", 
                      i, escData.esc[i].speed, escData.esc[i].current);
    }
}
```

### Motor Slow Rotation Detection (Optional)

In the EFTS scenario, developers can use the motor slow rotation interface to verify whether the FTS signal chain is functioning properly during the ground pre-check phase. The slow rotation detection flow is: start slow rotation -> query ESC status to confirm entry into slow rotation mode -> stop slow rotation.

#### Start Motor Slow Rotation

```c
returnCode = DjiFlightController_StartSlowRotateMotor();
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Start slow rotate motor failed: 0x%08llX", returnCode);
    return returnCode;
}
```

#### Get ESC Slow Rotation Status

After starting slow rotation, use `DjiFlightController_GetElectronicSpeedControllerStatus()` to query the ESC status and confirm whether all motors have entered slow rotation mode:

| Status Value | Description |
|--------|------|
| DJI_FLIGHT_CONTROLLER_NO_MOTOR_IN_SLOW_ROTATE_MODE | No motors are in slow rotation mode |
| DJI_FLIGHT_CONTROLLER_SOME_MOTOR_IN_SLOW_ROTATE_MODE | Some motors are in slow rotation mode |
| DJI_FLIGHT_CONTROLLER_ALL_MOTOR_IN_SLOW_ROTATE_MODE | All motors have entered slow rotation mode |

```c
E_DjiFlightControllerElectronicSpeedControllerStatus escStatus;

returnCode = DjiFlightController_GetElectronicSpeedControllerStatus(&escStatus);
if (returnCode == DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_INFO("ESC slow rotate status: %d", escStatus);
    if (escStatus == DJI_FLIGHT_CONTROLLER_ALL_MOTOR_IN_SLOW_ROTATE_MODE) {
        USER_LOG_INFO("All motors are in slow rotate mode, FTS signal chain verified.");
    }
}
```

#### Stop Motor Slow Rotation

```c
returnCode = DjiFlightController_StopSlowRotateMotor();
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Stop slow rotate motor failed: 0x%08llX", returnCode);
    return returnCode;
}
```
