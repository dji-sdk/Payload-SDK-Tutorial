## Overview

DJI exposes onboard Network RTK capability. Combined with the drone's 4G module connectivity, the Network RTK service can provide centimeter-level positioning accuracy. Through the Network RTK interfaces provided by PSDK, developers can configure NTRIP service parameters, start and stop the Network RTK service, and monitor the RTK service operational status in real time via callback functions.

:::tip Note:
 This feature applies to the Matrice 400 paired with Manifold 3.
:::

## Basic Concepts

### Network RTK Service States

During the operation of the Network RTK service, the current service state is reported via the state callback. The meaning of each state is as follows:

| State Enum | Value | Description |
|----------|------|------|
| DJI_LOG_IN | 0 | Logging in to the NTRIP service |
| DJI_CONNECTING | 1 | Connecting to the remote server |
| DJI_TRANSFER | 2 | Data transfer in progress; service started successfully. Note: This state does not mean RTK solution has converged — subscribe to RTK positioning data separately to verify accuracy |
| DJI_RECONNECT | 3 | Attempting to reconnect |
| DJI_BROKEN | 4 | Connection broken |
| DJI_STOPPING | 5 | Service is stopping |
| DJI_REBOOTING | 6 | Aircraft reboot required to switch RTK source. The aircraft will not reboot automatically — manually reboot and then call the start interface again |

### NTRIP Service Configuration Parameters

The following NTRIP parameters must be configured when starting the Network RTK service:

| Parameter | Max Length | Description |
|------|----------|------|
| account | 15 characters | NTRIP username |
| password | 63 characters | NTRIP password |
| host | 63 characters | NTRIP Caster address; only IP addresses are supported, not domain names |
| port | 5 characters | NTRIP port number (1–65535) |
| mountPoint | 31 characters | NTRIP mount point; only letters, digits, `-`, `_`, `.` are allowed |

### State Callback Registration

It is recommended to register the state callback function before starting the RTK service to receive service state changes in a timely manner. For the meaning of each state, refer to [Basic Concepts - Network RTK Service States](#network-rtk-service-states).

```c
static void ReceiveNetworkRtkStateCallback(E_DjiNetworkRtkOnboardState state)
{
    switch (state) {
        case DJI_LOG_IN:
            USER_LOG_INFO("Network RTK state: Logging in");
            break;
        case DJI_CONNECTING:
            USER_LOG_INFO("Network RTK state: Connecting");
            break;
        case DJI_TRANSFER:
            USER_LOG_INFO("Network RTK state: Data transfer in progress, service started successfully");
            break;
        case DJI_RECONNECT:
            USER_LOG_WARN("Network RTK state: Reconnecting");
            break;
        case DJI_BROKEN:
            USER_LOG_ERROR("Network RTK state: Connection broken");
            break;
        case DJI_STOPPING:
            USER_LOG_INFO("Network RTK state: Stopping");
            break;
        case DJI_REBOOTING:
            USER_LOG_WARN("Network RTK state: Rebooting required, please manually reboot the aircraft");
            break;
        default:
            USER_LOG_WARN("Network RTK state: Unknown state %d", state);
            break;
    }
}

returnCode = DjiNetworkRtk_RegReceiveNetworkRtkStateCallback(ReceiveNetworkRtkStateCallback);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Register network RTK state callback failed, error code: 0x%08X", returnCode);
}
```

### Start Service

Configure the NTRIP parameters and start the RTK service via the `DjiNetworkRtk_StartService` interface. After starting, monitor the state callback:

* If the state is `DJI_REBOOTING`: the current RTK source is not a custom network source. You need to manually reboot the aircraft to complete the source switch, then call this interface again after reboot to start the service.
* If the state is `DJI_TRANSFER`: the Network RTK service has connected successfully.

```c
T_DjiNetworkRtkServiceConfig config = {0};

// Configure NTRIP service parameters
strncpy((char *)config.account, "your_account", sizeof(config.account) - 1);
strncpy((char *)config.password, "your_password", sizeof(config.password) - 1);
strncpy((char *)config.host, "192.168.1.100", sizeof(config.host) - 1);  // Only IP addresses are supported, not domain names
strncpy((char *)config.port, "8001", sizeof(config.port) - 1);
strncpy((char *)config.mountPoint, "RTCM32_GGB", sizeof(config.mountPoint) - 1);

returnCode = DjiNetworkRtk_StartService(&config);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Start network RTK service failed, error code: 0x%08X", returnCode);
}
```

Recommended calling sequence:
1. Call `DjiNetworkRtk_StartService()`.
2. If the state callback reports `DJI_REBOOTING`, manually reboot the aircraft.
3. After the aircraft reboots, call `DjiNetworkRtk_StartService()` again.
4. Monitor the state callback and wait for the `DJI_TRANSFER` state, then subscribe to RTK positioning data to verify convergence.

### Stop Service

When the Network RTK service is no longer needed, call the following interface to stop the service. After stopping, you can receive the `DJI_STOPPING` state via the callback.

```c
returnCode = DjiNetworkRtk_StopService();
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Stop network RTK service failed, error code: 0x%08X", returnCode);
}
```
