## Overview

PSDK provides the camera stream acquisition feature. Developers can subscribe to real-time video streams from the FPV camera or gimbal cameras on the drone through the Liveview module, obtaining H.264 streams or decoded RGB image data for use cases such as storage, forwarding, decoding display, or AI recognition.

:::tip Note:
* Only applications developed using Linux and RTOS support the camera stream acquisition feature.
* When using this feature, you need to use a USB cable to receive the stream data from the drone camera.
* For Matrice 400, Matrice 4, Matrice 4D, and future drones, this feature requires Manifold 3.
:::

## Basic Concepts

### Camera Stream
PSDK provides the camera stream acquisition feature to meet the needs of applications developed using PSDK. It supports obtaining FPV camera or gimbal camera 1 H.264 streams and RGB images.

:::tip Note:
* The drone **supports getting H.264 stream from FPV camera and all gimbal cameras**.
* Since the callback functions for obtaining the FPV camera stream and obtaining the camera stream on gimbal 1 run in separate threads, the imshow module of OpenCV only supports running in one thread, so it only supports developers obtaining the H.264 stream and RGB image from either the FPV camera or the camera on gimbal 1.
* After obtaining the camera stream, please install a decoder such as FFmpeg to decode.
* For H.264 standard stream reference, please refer to <a href="https://www.itu.int/rec/T-REC-H.264-201906-S/en">H.264 Streaming Standards</a>.
:::


#### Camera H.264 Stream

By calling the `DjiLiveview_StartH264Stream()` interface and registering a callback function, developers can receive the H.264 stream from a specified camera. The SDK will automatically trigger the callback function when stream data is received, and developers can perform operations such as storage, decoding, or forwarding in the callback function.

:::tip Note:
For details about the UAV vision perception system (perception grayscale image stream, LiDAR point cloud, millimeter-wave radar point cloud, etc.), refer to <a href="./perception-data.html" target="_blank" rel="noopener noreferrer">Perception Data</a>.
:::

## Implementation

:::tip Note:
 When developing the camera stream acquisition feature using PSDK, please use the **Linux** or **RTOS** platform.
:::

:::warning Note:
The following code samples are provided as reference examples to help developers understand the calling workflow and implementation approach of each feature. Developers should adapt and adjust based on the actual hardware characteristics and application scenarios of their own payload devices.
:::

### H.264 Stream Acquisition

Call the `DjiLiveview_StartH264Stream()` interface, specifying the camera position, sub-camera source, and callback function. The SDK will automatically call the callback function to push data when H.264 stream data is received. Call `DjiLiveview_StopH264Stream()` to stop receiving.

```c
// Construct H.264 stream receiving callback function
static void DjiTest_PayloadCameraStreamCallback(E_DjiLiveViewCameraPosition position, const uint8_t *buf,
                                                uint32_t bufLen)
{
    FILE *fp = NULL;

    fp = fopen(s_payloadCameraStreamFilePath, "ab+");
    if (fp == NULL) {
        return;
    }

    fwrite(buf, 1, bufLen, fp);
    fflush(fp);
    fclose(fp);
}

// Start receiving H.264 stream
returnCode = DjiLiveview_StartH264Stream(DJI_LIVEVIEW_CAMERA_POSITION_NO_1,
                                         DJI_LIVEVIEW_CAMERA_SOURCE_DEFAULT,
                                         DjiTest_PayloadCameraStreamCallback);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Request h264 of payload failed, error code: 0x%08X", returnCode);
}

// Stop receiving H.264 stream
returnCode = DjiLiveview_StopH264Stream(DJI_LIVEVIEW_CAMERA_POSITION_NO_1,
                                        DJI_LIVEVIEW_CAMERA_SOURCE_DEFAULT);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Stop h264 stream failed, error code: 0x%08X", returnCode);
}
```

:::tip Note:
* After obtaining the H.264 stream, use the **ffplay -flags2 showall xxx.h264** command to play the H.264 file.
* Use the Sample `test_liveview` to obtain H.264 stream data and save it as a local .h264 file.
* Use the Samples `camera-stream-callback-sample` and `camera-stream-poll-sample` to decode H.264 streams with FFmpeg.
:::

### RGB Image Acquisition

Call the `DjiLiveview_StartImageStream()` interface, specifying the camera position, sub-camera source, pixel format, and callback function to receive decoded RGB image data. Call `DjiLiveview_StopImageStream()` to stop receiving.

:::tip Note:
* This interface is only supported on the Manifold 3 platform.
* Supported pixel formats include NV12, RGB Planar, and RGB Packed.
:::

```c
// Construct image data receiving callback function
static void DjiTest_ImageCallback(E_DjiLiveViewCameraPosition position, const uint8_t *buf,
                                  uint32_t len, T_DjiLiveviewImageInfo imageInfo)
{
    USER_LOG_INFO("Received image: position=%d, width=%d, height=%d, frameId=%d",
                  position, imageInfo.width, imageInfo.height, imageInfo.frameId);
    // Developers can process image data here, such as saving, displaying, or analyzing
}

// Start receiving RGB images
returnCode = DjiLiveview_StartImageStream(DJI_LIVEVIEW_CAMERA_POSITION_NO_1,
                                          DJI_LIVEVIEW_CAMERA_SOURCE_DEFAULT,
                                          PIXFMT_RGB_PACKED,
                                          DjiTest_ImageCallback);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Start image stream failed, error code: 0x%08X", returnCode);
}

// Stop receiving RGB images
returnCode = DjiLiveview_StopImageStream(DJI_LIVEVIEW_CAMERA_POSITION_NO_1,
                                         DJI_LIVEVIEW_CAMERA_SOURCE_DEFAULT);
```

### I-Frame Request

During H.264 stream transmission, you can actively request I-frame data via `DjiLiveview_RequestIntraframeFrameData()` to help the decoder quickly refresh the image. This is suitable for actively requesting key frames to recover when decoding errors or image corruption occur.

```c
returnCode = DjiLiveview_RequestIntraframeFrameData(DJI_LIVEVIEW_CAMERA_POSITION_NO_1,
                                                    DJI_LIVEVIEW_CAMERA_SOURCE_DEFAULT);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Request I frame failed, error code: 0x%08X", returnCode);
}
```

## Sample Tutorial

The following demonstrates the complete calling workflow for obtaining camera H.264 streams, based on the SDK sample code `test_liveview.c`.

### Initialize Liveview Module

Before using the stream feature, you need to call `DjiLiveview_Init()` to initialize the Liveview module.

```c
returnCode = DjiLiveview_Init();
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Liveview init failed, error code: 0x%08X", returnCode);
}
```

### Start Receiving H.264 Stream

Start receiving H.264 streams from the FPV camera and gimbal camera respectively. The SDK will continuously push stream data through callback functions.

```c
// Start receiving FPV camera stream
returnCode = DjiLiveview_StartH264Stream(DJI_LIVEVIEW_CAMERA_POSITION_FPV,
                                         DJI_LIVEVIEW_CAMERA_SOURCE_DEFAULT,
                                         DjiTest_FpvCameraStreamCallback);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Request h264 of fpv failed, error code: 0x%08X", returnCode);
}

// Start receiving gimbal camera stream
returnCode = DjiLiveview_StartH264Stream((E_DjiLiveViewCameraPosition)mountPosition,
                                         DJI_LIVEVIEW_CAMERA_SOURCE_DEFAULT,
                                         DjiTest_PayloadCameraStreamCallback);
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Request h264 of payload failed, error code: 0x%08X", returnCode);
}
```

### Periodic I-Frame Request

During stream reception, the sample code actively requests an I-frame every 5 seconds to ensure the decoder can periodically refresh the image.

```c
for (int i = 0; i < TEST_LIVEVIEW_STREAM_STROING_TIME_IN_SECONDS; ++i) {
    USER_LOG_INFO("Storing camera h264 stream, second: %d.", i + 1);
    if (i % TEST_LIVEVIEW_STREAM_REQUEST_I_FRAME_TICK_IN_SECONDS == 0) {
        returnCode = DjiLiveview_RequestIntraframeFrameData((E_DjiLiveViewCameraPosition)mountPosition,
                                                            DJI_LIVEVIEW_CAMERA_SOURCE_DEFAULT);
        if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
            USER_LOG_ERROR("Request stream I frame failed, error code: 0x%08X", returnCode);
        }
    }
    osalHandler->TaskSleepMs(1000);
}
```

### Stop Receiving and Deinitialize

After completing stream acquisition, stop stream reception for each camera in sequence, and deinitialize the Liveview module to release resources.

```c
// Stop FPV stream
returnCode = DjiLiveview_StopH264Stream(DJI_LIVEVIEW_CAMERA_POSITION_FPV,
                                        DJI_LIVEVIEW_CAMERA_SOURCE_DEFAULT);

// Stop gimbal camera stream
returnCode = DjiLiveview_StopH264Stream((E_DjiLiveViewCameraPosition)mountPosition,
                                        DJI_LIVEVIEW_CAMERA_SOURCE_DEFAULT);

// Deinitialize Liveview module
returnCode = DjiLiveview_Deinit();
if (returnCode != DJI_ERROR_SYSTEM_MODULE_CODE_SUCCESS) {
    USER_LOG_ERROR("Liveview deinit failed, error code: 0x%08X", returnCode);
}
```

## FAQ

### Errors When Decoding with Decoder
Restricted by the computing power of the computing platform, applications developed based on PSDK may encounter the following problems when encoding and decoding:
* Slow decoding: it takes a while for the decoder to decode the first frame
* Frame loss: insufficient computing power of the computing platform
* An error occurs when using FFmpeg to decode: Please try decoding on Ubuntu 16.04, and make sure that the RNDIS, USB and network port drivers are correctly installed in the application running the decoder, and ensure that the application can correctly identify the drone.

### I-Frames Sometimes Appear in H20/H20T H.264 Stream with GDR Encoding Format
The H20/H20T is a multi-lens payload camera. When DJI Pilot switches camera images, the camera's H.264 stream will insert I-frames to help DJI Pilot's image transfer images construct the image. Therefore, I-frames will appear in the H.264 stream, which does not affect the decoding process of the GDR format.
